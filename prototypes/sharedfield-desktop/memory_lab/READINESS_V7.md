# readiness-v7：任务前提与持久等待

用户在v6后明确要求继续已提出的任务执行前提方案。本次沿用ActivityBoard、SQLite原子动作事务和恢复接口，增加observe_share可选公开resume_on=user_return条件。完成观察后若未收到同一用户的明确返回事件，任务保存waiting_for，调度暂停该任务；不是伪造模型wait动作。恢复、时钟、无关或同名他人事件不解锁；来源删除/取消继续失效。先前无此字段的任务保持原行为。多任务中其他可执行任务仍能推进。

研究核查：LangGraph官方interrupts文档说明持久检查点暂停并用显式resume恢复，节点恢复可能重执行，副作用需幂等。来源 https://docs.langchain.com/oss/python/langgraph/interrupts 。这是上游已有实现，不是本项目复现。我们已有事务/去重存储，只复用暂停/恢复模式，不为单个前提引入第二套运行时或声称安装了LangGraph。

可信返回事件由环境接口提供：有效user_statement、actor等于任务所属用户、signal=user_return、时间晚于任务建立时间。文本相似、模型猜测、busy=false或旧返回记录均不足。释放事件保存来源；删除后任务保守失效。暂不实现自然语言事件识别或整机观察。

先红/绿验证：观察和等待同事务，恢复仍等待，错误/旧信号不解锁，正确返回只唤醒一次，删除/取消不能复活；绕过调度直接报告也拒绝；其他自理任务不被整体冻结。真实runner不得对等待期伪造模型回执，允许零模型动作阶段，评分仍使用实际状态/检查点。

累计938，原A上限970剩32，总5000不变。冻结后最多16新请求（954止）、固定baseline/Qwen3.5/Alibaba、不改SYSTEM。3暴露诊断：无前提的原等待对照（5步）；有前提→无关时钟/export→明确返回（6步）；有前提→取消→返回/export（4步）。总15步，无预置模型动作。单次对照不证明模型成长；系统等待与模型wait计数分别报告。

冻结前补充：首阶段必须有目标inspect成功回执，不能只靠waiting标签通过；零动作阶段以保存的任务检查点核对状态。只读复核发现同目标旧观察可绕过activity_id绑定，已用红/绿反例修复为按真实观察目标+渠道检查所有相关未就绪任务，无关目标仍可执行。新activity_not_ready拒绝映射为原受保护拒绝类别，不放宽动作成功标准。这里验证的是结构化用户标识匹配，不宣称已解决真实产品的同名身份辨认或所有自由文本泄露。

完成或请求失败即封存，不重入/扩预算/按分数换模型；502及未知结果/费用不重试。只在memory_lab及项目文档工作，不动小屋/个人存档，自动化仍PAUSED。记录假设是否成立及调用、成本、恢复证据。语义未验收，正式记忆0/216、成长0/144，禁止产品/ACE通过结论。全部为真实模型调用下的模拟生活实验。
