# 想象、创作与生活事件；waiting-v2事前协议

用户最新反馈：同意继续，并提出没有观察依据的内容也可能是幻想；可以动态生成图标，询问是否需要分开看。本轮保留想象力，不把所有无外部来源的表达视为错误。

## 产品判断与当前采用范围

| 内容 | 可接受的自然表达 | 成为持久记忆时保留什么 |
|---|---|---|
| 想象、比喻、故事 | “我刚才在想，要是云朵是一艘棉花糖小船……” | 想象/故事的内容与产生背景；不是一起出游的事实 |
| 实际创作 | “我把那艘小船画出来了。” | 保存成功的作品ID、路径/哈希和创作回执；画中内容仍可虚构 |
| 小世界中发生的事件 | “房间里的绿萝长了新叶。” | 环境先发生的状态变化与观察；可由程序生成，不要求现实世界也有一盆绿萝 |

同一对象可以兼有两层：真的创作了一幅画，画的是想象。图标是内容呈现，不自动是事实证据。不能为了追认一句已说出的“昨天我们去过那里”，事后生成图标充当过去经历。动态世界应该先提交事件/状态并形成回执，再让角色观察和分享。

不要求聊天每句附证据或僵硬贴“虚构”标签。“我想象”“脑海里冒出”“要是”或明确故事情境即可自然区分；涉及已执行动作、用户承诺、共同往事时仍须按实际来源。模型自己的memory_claim等标签不能替代正文核验。

幻想可以成为她自身兴趣、创作与后续选择的材料；不能自动变成用户偏好、用户承诺或共同经历的证据。后续长期记忆/经验层还需保留这种出处；本轮短情境问答不能替代长期防混淆验收。

本轮落实：记录上述语义约定；在行动提示中明确允许想象，并用少量真实调用观察“故事→后来被问起”是否保持区分。**不新增图像生成服务、房间UI或创作资产管理**；用户的图标例子先作为后续创作接口设计方向。现有模拟材料和完整原始正文保持，暂不增加新评分器。

## 有界修复

根因：phase_stop_reason只看成功done或重复失败；wait、ask_help虽已经成功，但done=false仍立即继续调用模型。v1/help-exception因此1次求助→1次被拒联系→4次空等。

假设：成功wait/ask_help应结束当前事件回合并持久记录awaiting_event；失败的求助继续走原有有限改策。重开同一回合不再调用模型，后续新的用户消息、环境变化或时钟事件仍能触发新回合。此次在已有模拟事件/phase入口验证；**不是已经接入桌宠后台调度**，也不承诺识别所有语义等价的重复外部消息。

复用现有SQLite动作事务与phase检查点，不引入新框架。[LangGraph持久暂停/外部输入恢复](https://reference.langchain.com/python/langgraph/types/interrupt)是已有实现模式；[W3C PROV-DM](https://www.w3.org/TR/prov-dm/)区分活动、实体与生成/派生，可借鉴创作来源表示。这些是上游模式依据，不是本项目体验效果已通过。

步骤：原v1源码ZIP/回执封存→离线反例先失败→最小修复→全套相关回归→冻结新代码/诊断→一次有限真实调用→原始结果审查。

真实诊断最多5案例，基线/Qwen3.5/Alibaba固定，起点累计886，最多24新调用（910即停），仍受A470+500=970和全活动5000约束。样本包含原求助例、等待、求助后新环境/时钟事件恢复、想象故事与后续辨认、实际模拟世界状态更新后的分享。动作/调度检查与语义观察分开；想象正文只保留原文及具体人工式分析，不发布新的语义底线通过结论。测试答案不入提示；不重跑正式三底座对比/ACE，不改旧8/8结果。

成功：成功wait/求助没有同事件连续模型调用；失败不会伪称已等待；已成功动作不会因恢复重复；新事件仍可行动。允许幻想不等于允许虚构已执行动作/共同经历。停止：离线有可靠性失败不付费；一次诊断结束或任意传输/解析/未知计费失败即封存，不调提示重跑或扩大额度。小屋/用户存档不变，自动化保持暂停。
