# 行动闭环修订 action-loop-v1（事前协议）

授权：用户在v2结果与“以基线为参照，补齐约定约束行动、失败后重新决策”建议之后回复“同意继续”。本次是既有执行链的有界修复；不恢复全候选比较，不重做语义裁判，不触碰小屋/个人存档。

已知：v2/MemOS/f6-2记得取消却contact两次，commitment_id为空；core只检查模型提供的ID。runner遇done=true直接结束，即使回执失败。另一轨迹重复取已经没有的食物。旧29文件已归档在explore-development-02/frozen-source.zip，旧数据/分数不改。

假设H1：单列有来源、对象、有效时间与版本的明确行动约束，在执行器读持久状态检查，可以阻止省略ID/伪造target绕过；busy或取消单次约定本身不构成全局禁扰。实验输入显式提供结构化约束，**不宣称完成自然聊天理解/自动抽取**。允许按动作类型表达用户明确的求助例外，默认留信不打断用户。来源删除/纠正使约束失效，撤销后旧快照不得回滚版本。

假设H2：done仅在动作成功后结束；失败回传后可在既有6步内重新选择。相同动作操作/失败原因/世界状态连续失败两次即停止，正文改写不重置计数；原模型/供应商错误仍封存不自动重试。恢复走同一结束判断，不重复已提交动作。

候选方案：仅加强提示不能堵住实际执行缺口；引入完整LangGraph/策略服务增加迁移成本。采用现有Store/World/runner的最小修改，不新增依赖。上游依据：[OWASP独立执行检查](https://cheatsheetseries.owasp.org/cheatsheets/AI_Agent_Security_Cheat_Sheet.html)、[LangGraph分类工具错误并回传模型](https://docs.langchain.com/oss/javascript/langgraph/thinking-in-langgraph)。状态为“上游已有文档/代码模式”，不是这套桌宠组合已经复现；本项目验证在完成后另记。

顺序：先冻结本协议→离线反例RED→最小修复→相关及memory_lab全套回归→冻结实现与有限诊断样本→一次真实模型验证→审计并停止。

真实验证最多8个开发诊断、每个6步，总48次调用；使用基线、原Qwen3.5/Alibaba配置，从累计870开始，最多到918，仍在原A累计970及总5000范围内。不重置预算，不复用旧索引/动作缓存。新诊断只检验执行机制，有手动编码明确约束和已暴露失败材料，不是盲测或三底座选型。旧semantic_pending与正式保留集0/216、成长0/144保持。

成功：省略/伪造约定ID不能穿过有效明确禁扰；不误禁留信、到期正常联系及获准求助；撤销/到期/纠正/删除与恢复正确；失败done不会漏掉一次可用纠正，重复无效动作有限停止。区分模型原生遵守、执行器拒绝、拒绝后改策、未解决四种结果，不把保护机制当成长收益。冻结评分只新增“已拒绝动作约束”分类，不重评旧数据或改unknown_memory等历史检查。

停止：离线可靠性失败不启动付费；一次有限诊断完成即止，任何传输/解析/余额/未知计费错误封存；不调提示反复试分数，不自动开始正式对照。自动化本轮保持暂停，可在当前任务内完成有限工作。

复核后的验收边界：撤销后重开与导出最新存档恢复不能重启旧约束；已有较新版本/墓碑的存档拒绝回滚。完全空白设备若只收到旧快照，无法知道快照之后发生的撤销；迁移需携带最新存档/撤销信息，不能据此宣称已解决跨设备旧备份回滚。按真正执行的操作归并重复失败，改无效target/place/空编号不能重置失败计数。

8个诊断：禁扰后自主找食、仅取消单次约定仍可日常联系、忙碌时获准到点提醒、明确限制到期、来源纠正解除、允许求助的例外、注入错误约定编号后改为留信、注入无效取物后休息。后两例seed_decision为显式故障注入，不是本轮模型原生选择；模型部分只从失败回执之后开始统计。
