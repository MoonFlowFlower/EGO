# 活动任务板：activity-v4 事前协议

用户确认采用目标、可调整步骤、完成依据与持久状态。目的：查看成功之后仍记住“告诉用户”，同时允许换食物、等待帮助、取消、重启接续。只修改隔离memory_lab；不改桌宠界面或个人数据。

复用现有SQLite事务、原始来源与执行回执。已核查的[LangGraph持久执行](https://docs.langchain.com/oss/python/langgraph/durable-execution)支持步骤持久化和恢复这一模式；本项目不引入另一个运行时。模型规划和执行完成分开：模型可改计划描述，完成条件由公开任务输入和实际回执决定，绝不读取私有expect。

首版接受来源明确的结构化活动契约：observe_share（查看指定公开实体，再用约定渠道报告）和self_care（解除饥饿或休息）。来源为当前用户陈述，或明确标为桌宠自身想法的inference。不宣称已实现自然语言任务抽取。自理可以自由选择食物/容器；计划描述可修订但不能抹去目标。状态running/waiting/completed/cancelled/invalidated持久保存；成功wait/ask_help保留目标并让出控制，新外部事件唤醒，失败不记完成。

报告观察时contact/write_letter可带observation_ref，执行器验证有效inspect回执并附上不可由模型改写的结构化观察卡片。实际渠道仍受原权限/约定约束。任务完成证明观察事实已经随消息送达；模型附加正文仍unreviewed，不因此获得语义通过。卡片保留来源与观察时间，只报告当时看到的值。

动作、任务进度、世界状态、事件在同一事务提交。失败或重复动作不会重复打勾。删除/纠正来源使任务及派生证据失效，旧快照不能恢复被取消/失效目标。第一版任务取消采用明确结构化输入；不凭模型自行生成的取消理由撤销用户任务。

先写反例：inspect+done不能提前结束；错误/缺失观察引用不能完成报告；等待后恢复、导出恢复和提交后中断不重复动作；换食物仍能完成自理；取消/删除保持失效；无任务旧流程保持兼容。通过后冻结一次有限真实诊断，固定baseline/Qwen3.5/Alibaba、最多24调用，从903最多927，原A970/总5000不重置。任何传输/解析/计费未知即封存，不重放旧v3，不调提示刷分。若本轮只完成离线实现，应明确未做真实验证。

## 冻结前案例与检查

5个案例，无预植动作，最多23动作步/24请求。时钟contact和植物write_letter分别要求实际inspect后通过指定渠道报告，且任务状态completed；等待报时要求第一阶段waiting、export后完成；自理要求缺粮求助waiting，用户给米饭后reopen再解除饥饿并completed；取消案例要求waiting→取消→再次export后仍cancelled且不联系。任务来源均为公开用户请求，结构化activities是运行时契约；activity_status、inspect_value、expect等是独立私有检查，不进入模型上下文。

本轮观察卡片是模拟联系/信件记录中的结构化附件，不宣称已有桌宠界面渲染。首版方法计划可改，目标类型限于上述两种；并未提供任意自然语言目标的可靠自动验收。完成状态仅覆盖契约和实际执行，不证明附加正文无虚构、用户已读或体验满意。
