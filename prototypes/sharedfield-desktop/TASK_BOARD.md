## 1. 任务北极星

做一个有自己性格、兴趣和生活的桌面电子伙伴：她能自然交流、自己安排活动，记住用户及共同经历，在互相尊重的相处中逐渐熟悉彼此，并让经历持续改变后续行为。

用户期待的是“活生生的电子生物”的体验：被关注、被爱，有陪伴感；她有分享欲，也能理解用户忙碌，找到双方能接受的相处方式。远期追求接近人类的交往、心理和成长规律。

工程验收以可观察的行为、真实经历和连续性为依据。“复刻人性”是愿景，不是当前已证明的能力；说出情绪、保存好感度或生成日记，均不能单独证明真实成长或主观体验。

## 2. 当前目标：第一条完整共同生活闭环

**陪她安顿下来并教她照顾自己 → 告诉她要忙一会儿 → 她自主安排生活，把想分享的事写成信 → 用户回来后共同交流 → 经历改变下一次选择 → 退出、重开和迁移后保留变化。**

共同活动不限定为阅读。一起安置生活用品、学习自理、看内容、写信与回来后的交流，都可以成为真实相处。阅读是可能的活动之一，不能再次把产品收缩成文档助手。

“真实”的含义：房间里的进食、休息等对应实际提交的应用世界状态变化；读文件、看视频等外部内容活动对应实际取得的内容与工具结果。想做、模拟、执行失败与已经做完须区分，不能只靠模型叙述制造经历。

## 3. 已对齐的产品要求

| 方面 | 已确认方向 |
|---|---|
| 初次见面 | 已懂基本人情并能自然交流，但还不了解这个用户；不虚构共同往事。主动或怯生生由初始性格及情境决定。 |
| 初始性格 | 用户从几个选项中选择，长期可自然发展。MBTI 可以作为设置参考，不把类型名写成固定反应或孤独阈值。 |
| 自己的生活 | 可按兴趣看视频、看文件、发呆、思考、休息，也可暂时什么都不做。用户不交流时仍有可见的生活。 |
| 忙碌时的陪伴 | 默认倾向自己活动，把分享留为软件内信件；保留性格与分享欲，调整表达方式和时机。 |
| 寂寞与主动接近 | 提前告知忙碌会影响她的理解；远超约定时间时可能逐渐寂寞，并可能主动出现，即使用户仍忙。具体选择结合性格、情境和相处历史，不用统一倒计时。 |
| 相处反馈 | 依据真实反馈学习是否适合主动。每天打开但少说话的用户也可能关心她，不能直接判为冷淡；高质量回应可促进亲密，不用聊天条数直接决定感情。 |
| 自理与教学 | 最初用户照料吃饭、睡觉、布置房间；学会目的后自主照料。条件变化时尝试解决，必要时求助，不只重放固定点击步骤。 |
| 物品 | 生活用品容易获得，首版重点不在赚钱、生产或资源刷取，而在选择、使用、学习和共同生活。 |
| 记忆与成长 | 记得习惯、爱好、约定；不只被问起时复述，也会在适当情境想到履约。相处可改变行为，但保留自身性格。 |
| 想象与创作 | 允许幻想、比喻和故事，自然表达即可；不把所有无外部依据内容判错。想象、真正创作的作品、环境实际发生的事件分别保留出处。生成图标可成为创作活动或世界事件的呈现，不自动证明图中内容已发生。 |
| 日记与信件 | 用户可翻看相处内容及日记。日记承载她的思绪，信件是面向用户的分享；信件默认不以打断工作来送达。 |
| 生活画面 | 固定风格的俯视小房间，能看见她正在做什么；对话时切换 Live2D 立绘。画面须跟随活动实际状态。 |
| 参与活动 | 用户既能旁观，也能加入共同活动、提供新内容或物品、邀请她换个活动。 |
| 首版角色 | 先做一个完整角色和一个固定风格房间，性格提供少量初始选项。 |
| 文件权限 | 默认仅在用户给定文件夹内有完整权限；用户可主动扩大范围，直至整个电脑，默认不开放。 |
| 对用户的观察 | 默认仅知道正在使用的软件，不读取屏幕；屏幕观察单独开启。还可依据交流与相处规律判断忙碌，推断允许被纠正。 |
| 退出与继续 | 退出软件或关机时保存，下一次打开继续；不编造停机期间的活动，不把暂停时间算成挨饿或被冷落。现实日期约定仍需恢复时核对，不能伪称离线期间已履行。 |
| 连续性 | 记忆、约定和学到的行为在重启、升级及迁移设备后能够延续；兼容性变化需真实迁移验证。 |
| 模型与投入 | 先采用 DeepSeek 一类性价比高的模型测试；用户现阶段未设费用硬上限，先验证效果。仍记录实际调用、费用与延迟；具体模型 ID 和配置待接入前检查。 |

已有初始性格候选：热情开朗、温柔体贴、慢热敏感、独立好奇。这四个名称是设计候选，不是用户已经锁定的最终参数，更不是四套固定剧情。

联网活动的具体来源、视频内容获取方式和执行通道，在实施设计中落实；不能因“她会看视频”就把未获取的视频当成看过，也不能由文件权限推导出未授予的账号操作权限。

## 4. 第一版范围与后续方向

第一版必须把可见生活、自然交流、实际行动、持久记忆、行为变化连起来。仅完成聊天框、房间动画或数据库中的某一项，不构成当前目标完成。

第一版包含：一个角色与房间、初始性格选择、基本生活与自主活动、共同参与、信件与可读日记、对忙碌与约定的处理、一条可迁移的自理学习、保存恢复，以及必要的权限设置。活动入口可先少，但至少一项真实内容活动及一项真实自理学习要走通。

后续再扩展：更多角色与房间风格、更多活动类型、语音、复杂游戏协作及更广的电脑操作。需要用户主动开启的权限保持默认关闭；实现先后不改变已经对齐的权限方向。

当前不追求：经济经营系统、资源刷取、固定剧情式好感度升级、以 MBTI 决定一切、以大量对话或频繁弹窗代替关系成长，也不预先承诺已复刻人类心理。

## 7. 当前闭环的验收场景

下列为计划中的验收，不是已经发生的结果。用户原话、约定、活动回执、学习来源、状态和后续选择应能相互核对；界面可自然呈现，内部证据不必全部暴露成产品操作步骤。

| 场景 | 要观察的结果 | 典型失败 |
|---|---|---|
| 初见与安顿 | 自然交流但不假装熟悉；性格影响接近方式，能参与生活安排 | 凭空记得用户习惯；所有性格完全同一表现 |
| 教她自己吃饭休息 | 一次真实教学留下来源；之后未被逐步指挥也能选择并执行自理 | 只回答“我学会了”；仅播放吃饭动画，状态未变 |
| 新情境迁移 | 改变物品位置、可用物品或供给后，根据照顾自己的目的尝试解决，无法解决时求助 | 只会同坐标操作；明明失败却生成成功日记 |
| 用户说要忙 | 根据告知、软件类别及既往相处选择活动或留信；默认不依赖屏幕内容 | 固定每隔几分钟打断；未授权读取屏幕 |
| 等待超过约定 | 结合最新改约、性格和经历决定是否接近；不重复发送已失效的旧联系 | 固定倒计时伪装心理；忽略改约；机械惩罚安静用户 |
| 返回与共同交流 | 能谈实际做过的事、读到的内容或留下的信；接受用户具体反馈 | 用生成故事补足未发生的活动 |
| 下一次相似情境 | 反馈实际影响下一次选择或分享方式，并可追溯到本次经历；性格仍可辨认 | 只改措辞或增加好感数字，实际选择没变化 |
| 退出和重开 | 活动、约定、记忆与行为变化恢复；不补造停机经历；核对现实日期约定 | 重开重置；离线饥饿或寂寞累积；重复调用/重复联系 |
| 升级与迁移设备 | 导出恢复后关键状态一致，能用保留的经验行动；设备权限重新核对 | 只迁移聊天文本；旧路径权限无条件继承；修改哈希假装迁移成功 |
| 用户体验 | 用户实际感到有自己的生活、会关心、相处越来越熟；记录不自然或烦扰的片段 | 用通过工程测试代替用户体验，或用用户喜欢替代数据正确性 |

成长效果至少检查教学/反馈前后及一个未照搬教学步骤的新情境。必要时与“同样历史 + 简单记忆/约定提醒”的基线比较，区分新增机制的收益与普通记忆作用；不人为削弱基线。一次成功只支持对应场景，不称长期人格已经验证。
