**执行顺序**
1. **F0**：在现有代码上扩展。`move_cost`、`poison_cost`、视野、初始能量改为可配置；新增基线 N（不挑食）、F（固执）；加入坍缩记录、进食计数、漂移后恢复时间。**用 001A 冻结配置运行时，结果必须与 001A 逐位一致**，并写测试强制检查。001A 的已有文件一律不改。
2. **F1 闸门 W**：只跑脚本基线，按 0.05 → 0.10 → 0.15 → 0.20 → 0.30 的毒性阶梯，采用第一个通过的值。阶梯用完仍不通过就停止报告。
3. **F2 闸门 L**：用 `pilot` 种子 0–2，按 L0 → L1 → L2 → L3 累加试跑，采用第一个两臂都通过的级。每一级的完整结果都要记下来，没通过的也要。L3 仍不通过就停止报告。调整依据只能是闸门里的绝对指标，**不能看 B−A 差值**。
4. **F3**：冻结配置（`master_seed=20261003`），记录 SHA-256，跑正式矩阵 2×2×5×400 代。在开发集上检查闸门 V，**不通过就判为无效，不访问保留集**。
5. **F4**：保留集评估和消融，按预注册判定，写出 `evidence/002A/REPORT.md`。

**预算**：F2 上限 6 GPU 小时，F3 加 F4 上限 6 GPU 小时。超出时先停下来问我。这是笔记本 GPU，跑长任务时会出现热降频，温度和时钟按 001A 的方式继续记录。
