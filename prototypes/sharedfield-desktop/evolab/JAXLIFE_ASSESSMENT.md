# JaxLife 评估（2026-10-02）

对象：https://github.com/luchris429/JaxLife ，提交 `28d97fe`（2024-08-11，此后无更新）。论文：arXiv 2409.00853（ISAL 2024）。

**结论**：作为参考设计有价值，不适合 fork 来当底座。EVOLAB 只借鉴思路，自己实现。

## 读代码确认的事实

- **规模与维护**：核心代码约 2000 行，2024 年 8 月以后没有更新。
- **许可证**：仓库里**没有 LICENSE 文件**。按默认规则作者保留所有权利，因此不复制它的代码。
- **选择方式**：没有适应度函数。能量降到 0 就死亡；能量超过阈值时可以繁殖，后代继承父代权重并加上高斯突变（标准差 0.01），是无性繁殖。只有在种群全部灭绝时才随机重新播种。
- **衰老**：维持生命的消耗是 `age/256 + 0.25`，随年龄增加。
- **给能量通道**：`hit` 动作取负值时，等于把能量转给附近个体。照料或喂食的行为通道是现成的，可作为 E3 照料者实验的参考。
- **环境遗传**：个体可以改造地形，改造会保留下来影响后代，相当于一种通过环境传下去的"文化"。
- **大脑**：带注意力实体编码的 LSTM。一生中只有隐状态在变化，**权重完全没有可塑性**。出生时隐状态清零。
- **与本项目无关的部分**：可编程、图灵完备的机器人是论文的核心卖点，对桌宠用处不大。

## 兼容性问题（实测或读码发现）

- `jax.tree_map` 在 JAX 0.10.2 中已删除，要加兼容层 `jax.tree_map = jax.tree_util.tree_map`（实测）。
- `requirements.txt` 漏了 matplotlib（实测导入失败）。
- `main.py` 在加 `--wandb` 时会引用不存在的 `args.tune`（读码发现）。
- 天气类地图构造 `TerrainState` 时缺少 `max_energy` 和 `bits` 字段（读码推断，未运行）。默认的 Perlin 地图可以运行。
- 世界状态里的 `t` 初始是 Python int，第一次扫描后变成 jnp 数组，导致第二次调用时重新编译。基准测试必须测第三次调用。

## CPU 实测性能

环境：云容器，4 核，JAX 0.10.2 CPU 后端，矩阵乘约 354 GFLOP/s。脚本见 `evidence/jaxlife_bench/bench_jaxlife.py`，数据见同目录的 `results.json`。

| 配置 | 热启动后速度 |
|---|---|
| 32 个体 / 8 机器人 / 32×32 地图 / 64 步 | 每秒 4.3 个世界步（139 个体步/秒） |
| 128 个体 / 32 机器人 / 128×128 地图（默认） | 25 分钟内没完成 3×256 步，即每秒少于 0.5 个世界步 |
| 512 个体 / 64 机器人 | 未完成，手动停止 |

对比论文：在单张 A100 上跑 2^16 步。按上面的 CPU 速度，最小配置也要约 4 小时，默认配置要以天计。

**推测（未做性能剖析）**：每个个体行动时都返回一份完整世界状态大小的差量，最后再求和，开销按"个体数 × 世界状态"增长。EVOLAB 的世界改为只写局部，避免这个问题。

## 采纳与舍弃

- **采纳的思路**：隐式选择、能量经济、衰老、给能量动作、环境漂移、`lax.scan` 加 `vmap` 的结构。
- **舍弃的部分**：可编程机器人、全世界差量的写法、多实体注意力大脑（对 Room-v0 来说过重）。
- **需要新增的部分**：可演化的终生可塑性规则、参数预算匹配的对照臂、预注册的判定、照料者（E3）。
