# 悠小喵的小屋 · 可体验框架 0.1

双击项目根目录 **打开悠小喵的小屋.vbs**。也可执行 `python -B -m desktop_pet.server` 后打开 http://127.0.0.1:18180 。仅使用本机Python标准库，无需Docker或手动部署数据库。

先点右上角设置选择初始性格。点小人/“面对面”进入真实Live2D；聊天、便签回信和生活创作调用OpenRouter，默认沿用已核查的Qwen3.5/Alibaba，遇429依序尝试后续Gemini配置；非429不自动重试。凭据仅在服务端读取原授权文件的codex key，不送入页面。走动、吃饭、休息在本地运行；不按固定时间生成模板信。

建议先试：教她自理 → 观察走到餐桌并吃完（状态才改变）→ 点击“写张便签”，写一件具体的小事 → “保存并请她读” → 等读完、写完，在信箱看回信。一次阅读约22秒、写信约19秒，之后等待模型返回；页面关闭会暂停未完成动作。“只保存”只存本地，不请她阅读或调用模型。

便签支持新建、编辑和重新打开，最多6000字。保存时检查版本，避免旧编辑窗口覆盖已改内容。回信使用完成阅读时的原文副本，可在信件下展开核对；同名同内容版本最多生成一次回信。失败会显示状态，不以模板替代、不自动重发。旧信保留，不改写历史。

生活分享v3：教她自理后，首次自己吃完饭、首次自己休息完，各留一封“生活记录＋原创想象”的信。事实短句依据真实完成状态生成，下面的“脑海里的小剧场”明确是模型创作的虚构。重启和重复教学不会重置首次自动分享次数。点击书桌可分享最近一件尚未写过的吃饭或休息经历；没有素材时说明原因，不播放空写信动画。可用 `--no-life-sharing` 关闭此功能，仅保留便签回信。

旧版生活散文曾出现主体错配和添写事件，历史失败仍保留；旧待发任务不升级、不自动重放。新格式在数据库、导出和页面中都区分事实与虚构，聊天的信件事实上下文只取真实记录和“写过虚构片段”这一事实，不把虚构情节当作共同经历。模型仍可能在普通聊天中犯错，这不是一般幻觉问题的完整解决方案。

生活信可展开动作来源。取消自理教学会停止相关未完成自主动作及待发信；删除来源会撤下关联派生信并阻止迟到输出发布。已经发生的动作不倒转。忙碌按钮不打断正在吃饭、休息或阅读的她。当前只是“生活事件触发创作”，不等于一般心理成长；生成内容偏童话，尚需用户体验反馈。

自然交流中“以后饿了自己吃饭，累了自己休息”“我要忙5分钟”“我回来了”“先写信，不要打扰”“我喜欢…”可记录对应教学/约定/原话；这是明确的小型解析和持久规则，尚不等于一般经验学习或性格成长。没有经过记忆实验选型或ACE收益验证。

本地数据：`desktop_pet/data/life.sqlite`。房间动作、信件、日记、原话与教学保存其中；关闭页面后暂停（连接丢失至多8秒检测），不补造停机经历。`data/workspace/`是当前唯一内容文件夹，支持UTF-8 txt/md便签，通过“写张便签”编辑或直接编辑文件。没有软件观察、读屏、视频获取或整机操作权限。

设置页“导出相处记录”下载JSON记录副本；这不是完整可迁移安装包，跨版本导入尚未实现。关闭后复制整个data目录可保留本地存档。当前是独立桌面窗口的功能框架，尚未加入透明悬浮、系统托盘与自动置顶。

资源：原创临时房间小人来自已接受的GPT Image图集，通过CSS使用原图；房间是可交互SVG。Live2D为用户提供的悠小喵免费包，本地导入仅用于显示，未送入AI，不随发布分发；保留原使用须知。房间小人与Live2D外观不同是既有临时素材限制。

渲染复用 [pixi-live2d-display](https://github.com/guansss/pixi-live2d-display) 0.4.0 + PixiJS6.5.10，官方Cubism Core本地缓存；来源和哈希在web/vendor/lock.json。公开发布前须处理对应许可及素材授权。

开发检查：`python -B -m unittest discover -s desktop_pet/tests -v`。UI检查和模型实际调用结果见evidence/。体验版与原SharedField、个人存档、memory_lab实验数据完全分开。
