# 生活记录与原创想象分离：有界验证结果

采用用户此前认可的真实活动/幻想分开要求，替代actor-v1/v2让模型自由散文同时报告事实的做法。旧失败不改分。本轮验收的是新分区格式，不是证明旧散文可信。

## 已交付

- `letter_content.py`从实际进食/休息变化构造简短事实句；模型只能返回虚构片段，无法覆盖事实句。
- 信件保存`fact_text`、`imagination`，纯文本`text`保留虚构标记；页面分区显示。聊天中的信件事实上下文排除虚构内容，仅保留事实记录和创作存在记录。
- v3默认启用，原有首次进食/休息各一次自动触发、手动邀请、失败不重发、取消及删除失效保持。`--no-life-sharing`可关闭。旧生活散文待发任务封存，不升级重放；旧信保留且旧生活散文不进入新的信件事实上下文。

## 证据

事前协议：`../life-sharing-v3-plan.md`。固定Qwen3.5/Alibaba两次，无切换、重试，USD0.000068770。

自主进食案例：food由5变4、hunger下降，事实句正确说明桌宠自主完成并用上教学。用户邀请休息案例：energy恢复，事实句正确说明是桌宠休息、用户发出邀请。创作分别为餐盘/云朵、呼噜声/云朵的幻想，两者均以“如果”开头。虚构的用户、云朵、动物不被当成现实事件评分或存入事实。

真实模型入口是一次性`python -B -m desktop_pet.verify_life_v3`，此目录存在即拒绝重入。动作经真实Life执行和状态提交，但测试加速推进模拟时钟；不冒称真实时间长期陪伴。模型结果已保存，再用隔离18181服务载入检查UI，不另发模型请求。`letters.png`为实际页面。提示、源动作、原始输出、回执、初始与最终源码哈希均在本目录。

31项最终回归通过，`tests.txt`；JS语法检查通过。故意含“用户醒来/紫色鲸鱼”的输出验证无法覆盖事实句或进入信件事实上下文；保存重开、旧任务不复活、默认入口触发v3、关闭开关不派发也通过。生成提示和事实构造在付费后未修改；付费后有默认配置/旧任务迁移/UI空态修改，范围见`review.json`，这些改动以离线回归验证。

## 使用与限制

代码已保存，18180日常服务未运行；此前启动曾被自动审批拒绝，本轮未绕过或重试产品启动。用户通过原VBS启动可加载新版。测试未写入个人存档，SharedField和memory_lab保持原状。

可体验“教自理→完成真实动作→记录＋创作→信箱查看”。此格式故意将真实记录写得朴素；创作偏童话，不代表自然个人反思。普通聊天仍可能产生不实内容，用户把故事再讲进聊天也不在本轮保证范围内。长期记忆选型、一般成长与自然陪伴仍未验收。
