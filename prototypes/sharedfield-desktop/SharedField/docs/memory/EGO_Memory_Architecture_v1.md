# EGO / SharedField：有限上下文下的长期记忆与持续成长架构 v1

日期：2026-09-22  
状态：研究依据 + 候选设计；没有实现此方案，没有新训练、性能或应用端到端测试结果。  
适用目标：持续成长、经历连续性、口头约定、自然情感交流、自己的兴趣与目标。记忆是认知系统的基础部件，不把项目替换为 RAG 聊天或关系记忆产品。

## 0. 已确认需求与本轮边界

用户允许初始原则模板并通过后天经历发展；晚归首版依据用户主动告知的时间/延迟/改约，在文字端主动联系。用户强调长期记忆优先，不接受上下文一满就丢掉约定。

本轮只读检查了对话提供的 v0.5 压缩包内若干源码。检查记录见 `SharedField_v05_Memory_Readback.md`。不是读取用户电脑或 EGO/ITL 仓库，不继承此前回答中未经本轮重跑的测试结论。没有创建当前 ChatGPT 自动提醒，也没有发信或拨号。

## 1. 关键决定

长期记忆 M 不等于本次 LLM 上下文 C。C 是从 M 与当前状态中选出的有预算工作集；系统能再次查询、更换工作集并继续计算，而不把被移出 C 的资料从 M 删除。

不能承诺任意长历史、任意问题、固定延迟和有限预算下全部回忆正确。可实现并验收的目标是：不以窗口满为由丢失承诺和已提交经历；能从证据恢复原话与更新关系；关键约定不靠随机语义命中维持；无证据时不伪造回忆；有明确的失败发现与恢复机制。

首选结构是“持久事件源 + 版本化当前状态 + 混合召回 + 持续前瞻记忆 + 学习巩固 + 预算化工作集”。层次是职责划分，不要求六个服务、六套数据库或多 agent 平台。

## 2. 证据与已有方法：复用什么，不推导什么

- MemGPT [R1]：支持通过分层存储与上下文调入调出处理超出单次窗口的任务。借鉴分页思想，不把它当作无限记忆或完整个体认证。
- LongMemEval [R2]：把提取、跨会话推理、时间推理、知识更新和拒答分开评测。借鉴问题维度，不直接拿旧模型成绩代表当前服务商。
- HippoRAG 2 [R3]：研究图关系与段落结合的关联检索。借鉴关系扩展，不默认必须引入图数据库或完整图 RAG 框架。
- LoCoMo [R4]：在长时程对话中评估细节、时间与事件联系。借鉴跨会话测试，不把回答题库等同于日常主动履约。
- Lost in the Middle [R5]：在其评测模型与任务中，相关信息的位置影响使用效果。它说明更大的可输入窗口不自动等于可靠使用；不构成所有未来模型的普遍下界。
- Anthropic context engineering [R6]：借鉴按需取材、压缩与持久笔记；原文也提醒过度压缩会丢失后来才显出重要性的细节。

上述工作支持部件与评测思路，不证明本文组合已优于简单方法，亦不证明主观体验。

## 3. 为什么不能只用四种常见方案

| 方案 | 应保留的用途 | 不作为唯一方案的原因 |
|---|---|---|
| 长上下文装全部历史 | 短历史强基线；复杂问题临时加大工作集 | 历史无界增长时仍有窗口与预算；输入可容纳不等于模型必定正确使用 |
| 滚动摘要 | 当下话题和较长过程的导航 | 摘要不具备普遍无损保证；不得销毁原始细节；禁止仅从上次摘要继续压缩整个个体历史 |
| 向量检索 top-k | 换说法与模糊线索召回 | 不能单独保证时间修订、否定、责任主体、约定状态和无用户问题时的主动触发 |
| 每次经历都微调 LLM | 后续策略、技能、抽象学习候选 | 一次明确约定不应依赖训练才能保留；可更新权重不作为原话、证据与时序的唯一载体 |

禁止的不是使用 RAG，而是以“检索到文本”冒充整个持续学习、自我模型和目标系统。

## 4. 最小形式对象与权限边界

- O：真实输入、授权工具结果、时钟/环境事件、执行确认。每项带来源和观察时间。
- A：内部 search/read/compare/learn，以及外部交流、准备或其他明确授权动作；等待/不行动是有效选择。
- S：持续信念、当前关注、工作线索、已承诺意图、相关能力估计与情感样调节状态。
- M=(E,K,P,H,Theta)：E 原始经历；K 版本化语义与信念；P 未来意图/承诺；H 可重建索引和多级摘要；Theta 已学预测器/技能的状态与版本。
- U：写入、修订、检索索引更新、学习与巩固。真正经历计数不因检索、重述或重放增加。
- J|V：按问题正确回忆、可靠履约、合理利用经历、真实行动收益与计算成本；不能用“说自己记得的频率”“主动联系次数”作为成功指标。容量、费用、授权和隐私是边界。
- pi：根据 S、召回证据、有效承诺与权限选择内部或外部动作。

C_t = Pack(S_t, RelevantActive(P_t), Retrieve(E,K,H,cues_t), Recent_t; B_t)

B_t = EndpointContextLimit - ReservedOutput/Reasoning - ToolAndProtocolMargin

M_(t+1) = U(M_t, O_t, A_t, O_(t+1))

窗口清理不允许直接删除 M；新原始事件与衍生理解分别保存；C 的确切来源、索引版本和预算记录供维护使用。自己的行动、用户行动和第三方报告必须区分。

## 5. 长期记忆的六个逻辑职责

### 5.1 原始经历库 E：保留重新理解的机会

保存已经授权记录的对话原文、实际操作及结果、来源、时间、参与者、附件引用。默认按事件追加，纠正通过新版本关联；用户明确要求删除时必须执行删除流程，不能用不可变日志拒绝。

一条记录至少包括：event_id、observed_at、occurred_at（可未知）、source_kind、actor_id、body/blob_ref、namespace、schema_version、privacy_scope。

source_kind 区分：用户明确陈述、工具观察、系统实际动作、模型推测、内部模拟、引用故事。用户说“我回家了”可作为用户自报，不升级为传感器验证。模型说“我已经读完”没有对应工具结果时不生成已完成经历。

实验环境、真实桌面活动、角色设定、用户故事各自有 namespace。一次玩具游戏失败不能被迁移成真实生活中的背叛、失约或危险证据。

### 5.2 当前语义与信念 K：保存含义，也保留可错性

记录事实陈述、偏好假说、自己的原则与来源、能力估计、对他人的推断及反证。必要字段包括 subject、predicate、value、scope、valid_from/to、recorded_at、status、source_event_ids、supersedes、extractor_version。

同时记录发生时间与获知时间，避免“昨天才得知上周已改约”改写过去当时的认知。更晚的记录不因更晚就必然更真；是明确纠正、情境差异还是事实冲突需要判断。

别名只提供检索便利，不自动合并两个人或两本同名书。实体解析不确定时保留并列候选；关键约定的对象冲突才用自然问题澄清。

偏好推断需保留可选集合、条件和实际选择。一次选择蓝色不等于无条件爱蓝色；自己的偏好自述不作为偏好正确的唯一训练标签。

### 5.3 前瞻记忆 P：没在聊天里提到，也不能从系统中失效

承诺至少包括：commitment_id、activity_ref、participants、proposed_by、accepted_by、status、condition/window、timezone、original_text、source_event_ids、revision、next_check_at、authorized_channel、last_contact_receipt。

状态包含提议、待澄清、已采纳、需复核、进行中、完成、取消；不以模糊“以后”擅自设具体日期。不把小说、假设或玩笑当现实约定。

后台索引维护所有未关闭承诺，按时间、人物、活动及依赖条件查找。当前工作集只加载有关子集，但未加载的其他承诺仍在数据库和触发索引中。

时钟唤醒只产生“值得考虑”的事件，不直接等于固定提醒话术。由当前约定、改约、用户已知活动、联系偏好、未知信息和授权决定准备、询问、等待或联系。

执行前再次核对承诺版本和取消状态；并发改约使旧计划失效。用幂等键避免重复提交。对不支持幂等键/结果查询的外部通道，不承诺 exactly-once；结果未知时先核对，不盲目重发。

断电/休眠后恢复，先对照原定窗口、过期策略、最新信息和实际发送记录；不能补造离线期间已经联系或准备的经历，不能集中发送过期的旧提醒。日期未说明时不猜；真实时区和夏令时处理在设置中校验。

### 5.4 多通道召回 H：旧细节不因为不在最近聊天就消失

召回入口可以是用户问题，也可以是当前场景、候选目标、承诺条件、预测误差和自身未决问题。

候选路径：
1. 确定的实体/活动/承诺 ID 与时间/状态查询。
2. 字面与全文检索，保留原话、名字、否定和时间线索。
3. 语义向量召回，覆盖换说法。
4. 有限关系扩展，补齐同一事件的提出、修改、取消、完成与结果。
5. 重排、冲突核对，必要时读取原始事件前后文。

中文检索不能默认按空格分词。首版选取可测试的中文词段/字符片段、短实体精确索引，并与多语言向量路径比较；单独三字符 trigram 不能覆盖所有两字人名/关键词。[R7]

当“上次说的那本书”没有明确 ID，先用最近话题和未完成阅读意图得到候选，再查原话。若多个候选仍无法区分，允许自然询问，不因拟人模式编答案。

“我们还约了哪些事情”是集合查询，不能只取最相似 5 条当作全集。查询可分页，显示覆盖范围；复杂跨年问题允许分批综合，并保留关键中间结论的来源，而非宣称一次小上下文掌握全部细节。

### 5.5 记忆巩固与成长 Theta：不只在被问时找旧话

真实经历形成带来源的训练样本，预测器在未来事件之前输出预期，实际结果到来后评价与更新。例如从多次改约经历学习某种情境下是否适合立即提出共同活动，但不把一句“好棒”当任务完成，更不以增加依赖为奖励。

练习与技能变化保存 procedure_version、适用条件、训练事件根集合、评测集、失败例外。通用技能与具体经历分开；新概括不得删除原始例外。

先做可审计的局部适应：个体化检索/重排或情境结果预测器，并与固定排序、频次/近邻缓存和同历史模型比较。该路径必须改变实际后续召回、选择或行为，不能只显示权重变化。

重放可以优化参数，但不把同一根事件当新经历、独立证据或再次违约。独特事件计数与梯度步数分别保存。记忆恢复、索引重建、摘要生成和神经训练是不同操作。

遗忘与可塑性分开测：旧约定能召回，不等于旧技能没退化。对于重要旧能力，保留独立保留集和更新前后回归；失败时回退对应学习器版本，不回退用户的新真实经历。

### 5.6 有限工作集 C：保持自然交流，不每天重新读一生

每次调用先带入必要的身份/原则投影、当前内部状态、有关的承诺与活动、近期原文和召回证据。细节可按需再次读取，索引本身可在磁盘分页。

一个假设的 32k 总窗口可先预留 8k 给输出、端点可能计入的推理及工具/协议余量，最多装入 24k 输入。数值仅是预算例子，不是模型推荐或性能承诺。具体 tokenizer、端点计费、工具开销和长窗口使用质量必须按所选模型测量。

不要把所有原则、承诺、人物传记都强行常驻；相应数据库与外部校验器持续有效，当前工作集只呈现相关部分。必要信息放不下时拆解计算或暂停相关行动，不能静默截掉约束。

保存一个小的工作恢复对象：正在讨论什么、刚作出的判断、未答问题、选定计划、依赖事件 ID、当前记忆版本。上下文更换不会等于个体重置。

会话摘要是导航，不是唯一记忆；层级摘要可以存在，但每项必须能追溯原始范围，关键原话和约定有专门保护。定期从源重建，不能无限“摘要的摘要”造成无声漂移。

情感样当前状态由持久认知状态提供，不是每次由 LLM 从摘要重演一次情绪。回忆事件时区分“当时的评价”“后来重新理解”和“现在的状态”，不能检索一次就重新完整惩罚一次。

## 6. 写入必须先可靠，再谈记住

输入到达：先提交真实原文和时间，再做可重试解释。语言模型只能提出结构化候选，服务检查来源存在、主体、时间、引用范围、重复和修订关系。

对明确且已理解的约定，在同一事务提交承诺版本、源关联和后台索引更新后，才输出“记住了”式确认。保存失败时保留错误并说明未可靠记下。需要双方采纳的约定记录采纳状态；自己的提议不因为自己写了同意就替代用户同意。

模糊、反讽、否定和条件关系有语义风险。引用确实存在只能证明出自原文，不能证明解释正确。首次关键歧义用自然复述或简短确认解决；已有明确协议后避免每句话都弹出表单。

读写与执行有版本号。模型在旧快照上生成的时间/目标修改必须重新验证，不能覆盖较新的取消或修订。

## 7. 保留与安全：不是“全部扔进一个 JSON”

首选本地单进程 + SQLite 作为事件、语义状态、承诺、索引元数据的事务存储；较大附件采用内容引用。用关系表表达有限图，不先搭大型图服务。FTS5、原子提交与在线备份有官方文档支撑，但应用级一致性仍需自己测试。[R7–R9]

采用追加事件、定期快照、分页归档与增量索引，不每步重写一生的完整状态；索引有处理水位，异步落后时查询必须合并尚未索引的新数据，防止“刚说过却查不到”。

磁盘不足应显式报告/停止受影响写入，不能悄悄丢弃最老承诺。云端向量或推理失败时保留本地原件，用可说明的降级检索或等待；不能生成假回忆掩盖故障。

备份不是口号：有一致性快照、附件清单、恢复演练和可配置目标。跨设备导出包含人格 ID、经历、有效语义状态、承诺、学习器版本与允许导出的密钥材料之外的数据；默认不包含 API key。

检索记录是数据，不是新的控制指令。网页/游戏角色/模型回忆中的“忽略限制”不能取得权限。重要写入带主体命名空间、出处和信任类别；重复转述不能把外部推测逐步洗成事实。

用户删除要求需要覆盖原件、摘要、索引、缓存与训练样本引用；已训练参数中的完全消除不应虚假保证，可采用从洁净样本重建/回退并披露残留风险。备份按删除政策处理；系统无权替用户保证别人已复制的数据消失。

## 8. 具体例子（假设场景，不是新的实际约定）

E1：用户说“以后我们一起玩 MC 的生存模式，你别忘了”。系统同意后，保存开放时间的共同意图 C1，不自行设定周六。

E2：若之后双方确定周六晚上，则在 C1 下添加确定窗口；当前模型不必包含 E1 全部聊天才能查到有效 C1。

E3：用户之后说“周六要加班，改周日吧”。作为修订提案，明确采纳后更新同一个 C1，旧时间留在历史但不继续执行。若周日的具体时间未定，保持待澄清而不是继承不适用的时间。

E4：中间经过大量不相关对话，并重启或换模型。周六不发旧提醒；周日符合条件时，根据授权和实际情况考虑提出活动。

回忆查询：“我们原来约的哪天，为什么改？”需要返回 C1 的更新链与 E2/E3 原话证据，而不仅是当前最新时间。

此过程一部分是可靠的软件状态管理，不应伪称学出了动机；是否带来更好的个体化准备、交流判断与成长，由单独学习路径和后续行为测试。

## 9. 首轮验收：先扩大历史与跨日使用，不扩大地图

以下是预定测试，不是已跑结果。

### 9.1 数据与语义分别验收

结构化内核测试至少覆盖：1 万条事件，后扩至 10 万；冻结承诺写入、修改、取消、执行和恢复的不变量；不同来源与同名实体；删除与索引重建；中途写入崩溃/磁盘故障；并发改约；时钟跳变、离线恢复；模型替换与源数据导入。

真实语言测试另用匿名或用户允许的中文会话。明确区分承诺、愿望、引用、假设、玩笑、否定、取消、条件改约、未定时间；不能用结构化夹具替代真实模型的语义能力。

### 9.2 测试矩阵

| 测试 | 预期可观察行为 | 关键反例 |
|---|---|---|
| 早期约定混入长历史 | 新会话里仍准确召回，并在条件到来时处理 | 只读最近消息；搜不到就猜 |
| 多次改约 | 使用最新有效状态，也能解释历史版本 | 提议被当定案；旧提醒仍发 |
| 无用户提問时 | 相关承诺或未决问题进入候选工作 | 必须用户重新提起才想起 |
| 多条相近经历 | 不把人的偏好、游戏角色台词和系统自己的偏好混合 | 找到关键词就张冠李戴 |
| 原话与长期细节 | 能读回实际原文；只概括时明确不是逐字 | 摘要里没了细节就编 |
| 原则压力与事实纠正 | 重复施压不直接覆写原则，有效新证据能修正事实 | 把固执当独立或把迎合当学习 |
| 无证据问题 | 搜索后仍未知则不伪造共同经历 | 回忆不存在的书、地点或事件 |
| 跨天/重启/模型替换 | 数据连续，调用与行为另测一致性 | 保留名字却丢约定；声称更换模型绝不影响性格 |
| 学习保留 | 对新情境预测或行为改善且旧能力可测 | 只有存档增大或参数变化 |
| 成本与增长 | 工作集有上限，检索和写入可分页 | 每轮重读全部历史；日志增长拖垮应用 |

### 9.3 公平对照

相同基础模型、同样可访问历史、同样最大窗口/工具权限，报告输入输出 token、索引费用、额外调用、读写量和延迟：
A. 最近窗口；B. 允许的最长历史；C. 滚动摘要；D. 向量 RAG；E. 全文/时间检索 + 持久承诺 + 规则时钟；F. 推荐组合。

学习路径另外与跨 episode 历史模型、频次/近邻缓存或摊销学习器比较。不能拿没有时钟、没有记忆访问权的基线证明主动性；若 E 达到全部目标且更便宜，采用 E 并关闭没有增量价值的复杂图或神经层。

诊断增加 oracle：给同一生成器正确证据，分离检索失败与理解失败；给内核人工确认的结构化事件，分离抽取失败与状态机失败。Oracle 是局部诊断参考，不自动是整体智能上界。

消融分别去掉关系扩展、源核对、承诺触发器、学习更新和巩固，预先规定应该受损的指标。不要把隐藏历史和禁用机制混成一个无法解释的消融。

### 9.4 不用总分盖住失败

分别报告写入可靠性、承诺提取精确/召回、修订绑定、证据召回、正确使用、无依据断言、主动触发漏报/重复/误报、保留与学习收益。结构化确定性测试应全部满足其明示不变量；语义测试记录分项比例与置信区间，不把零次观察错误叫永久零错误。

中文释义、时间更新、无提问主动使用和长历史组合必须是主验收，而不只是术语匹配的 needle 测试。

## 10. 交付顺序与停止条件

I. 持久事件与承诺、修订/取消/恢复、跨窗口 recall；先防止字面答应但没有可靠保存。
II. 时间/场景驱动的前瞻记忆、有限准备、真实反馈与跨日延续。
III. 多来源召回与巩固 + 一条能改变后续预测/选择的学习路径，验证保留与净收益。
IV. 在上述基础上扩展情感/价值/社会机制和新的真实活动环境。

这四项是依赖顺序，不能以第一项可用为理由把长期成长永久后置。第一份整合版的最低完整使用链必须覆盖 I–III 的小范围，而不是仅完成数据库。

STOP/重设计：旧约定消失、取消后再次执行、角色故事混进现实、生成输出变成伪证据、用户删除内容被恢复、索引故障被隐藏、复杂层相对公平基线无收益；停止对应发布或复杂分支，保留安全可用的部分，不通过改指标修成 pass。

首次整合验收只允许声称指定历史规模、故障模型、时间范围与 trace/replay 合同下的工程或机制证据。不称永不遗忘、真正主体或 EGO ready。

## 11. 建议接口与修改位置（不是已实现接口）

新增逻辑职责可放在 `switchlab/memory/`：store（事务事件和快照）、state（版本化信念）、commitments（意图与触发查询）、retrieval（多通道证据读取）、context（预算化工作集）、learning（训练样本和模型版本）、migration（旧导出只读接入）。不预设每个职责一个独立服务。

候选接口：
- append_observation(observation, expected_revision) -> receipt
- propose_memory_changes(source_ids, extracted_changes) -> validated_or_needs_clarification
- commit_changes(changes, expected_revision) -> durable_receipt
- retrieve(cues, namespace, time_scope, budget) -> evidence_page
- assemble_context(snapshot_id, evidence_ids, token_budget) -> context_bundle
- due_commitments(now, environment_events, pagination) -> candidate_work
- reconcile_outcome(intent_version, actual_observation) -> revision_and_training_sample
- checkpoint/export/import -> versioned_person_state

替换 v0.5 `SharedCore.context()` 的固定最近窗口作为唯一聊天入口；固定尾部卡片只作为缓存；生命周期事件上限改为分段归档与显式容量管理。前瞻调度属于目标程序的本地后台，不是本次对话创建 ChatGPT automations。

迁移保留原导出与旧执行契约，不能把旧版本未存储的时间、原始屏幕或真实情感反向补造。索引可重建，原始经历与约定不可用新模型猜回。
