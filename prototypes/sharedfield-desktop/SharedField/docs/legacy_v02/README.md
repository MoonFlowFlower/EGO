# SwitchLab Studio v0.2
## 可以对话、持续处理目标、保存产出并从反馈调整的本地研究工作台

这版不是“聊天窗口给旧模拟器配旁白”。语言可以提出或修订持久目标，内核执行已允许的本地步骤，把实际草稿或数值实验结果写入历史，下一步使用这些结果。没有任务时不调用模型；产出待验收时等待，不自行循环生成。

**这是部分闭环工程原型，不是完整 EGO，也不是机制优越性、真实自主或主体性证明。** 语言理解由你连接的模型提供。目标与调度规则有工程先验；没有训练一个新的“自主大脑”。真实服务商的语义表现仍须你本地测试。

## Windows：第一次使用

1. 完全解压到普通目录，不要在 ZIP 内运行。打开 `SwitchLab`，双击 `START_WINDOWS.bat`。需要已有 Python 3.10+；程序不自动安装任何东西。
2. 浏览器打开本机 `http://127.0.0.1:8770`。窗口不自动打开时手动输入此地址。不要关闭命令行窗口，它运行本地服务。
3. 点右上角 **模型连接**。选择已有的远程兼容 API 或本地模型，填模型 ID、地址及必要密钥。远程接口必须明确同意发送所选上下文。保存后可点“发送最小连接测试”。该按钮会实际请求模型，可能计费。
4. 发消息，检查对话和右侧目标。再点 **允许 6 步后台推进**，允许系统在没有新消息时继续做现有工作。可随时暂停。
5. 打开实际草稿，按原始约束给“符合验收”或“未达验收，继续修订”。“仅表达偏好”是另一通道，不增加任务成功奖励。

通用启动：

```bash
python run.py studio
```

端口冲突：

```bash
python run.py studio --port 8771
```

Linux/macOS：`sh START_LINUX_MAC.sh`。无第三方运行依赖，无内置模型权重，无 API key。

## 模型连接的三个选择

| 模式 | 设置 | 边界 |
|---|---|---|
| OpenRouter / 其他兼容接口 | OpenAI-compatible Chat Completions；填写真实 base URL、模型 ID、key | 可能收费；各模型 JSON 输出质量不同 |
| 已部署的本地服务 | 例如 Ollama 兼容端点 `http://127.0.0.1:11434/v1`；填已安装的模型 ID | 程序不会下载或部署模型，不保证任意模型能稳定遵守协议 |
| 手动交换 | 保持默认模式；发送消息后打开“手动语言交换”，复制整段请求给真实聊天模型，再贴回 JSON | 不需要 API，但每个语言步骤需你传递，不能无人值守完成语言计算 |

API 使用 `POST /chat/completions`，模型列表使用 `GET /models`。默认请求 JSON mode；不支持时在兼容设置中关闭。输出仍要符合严格 JSON 合同，没有“失败后生成假回复”的备用模式。模型为空、鉴权失败或额度不足会停止并显示错误。

**ChatGPT 订阅与 API 计费分开。** 程序不读取浏览器登录凭据，不绕过服务商额度，也不把订阅当成 API key。你不需要把 key 发给聊天助手，在本地界面填写即可。

供应商文档（2026-09-21 核查）：
- OpenRouter: https://openrouter.ai/docs/quickstart
- Ollama compatibility: https://docs.ollama.com/api/openai-compatibility
- OpenAI billing separation: https://help.openai.com/en/articles/9039756

## 先试这一段

> 我想做四人合作探索游戏，保留发现隐藏路线的乐趣，但制作成本不能高。不想做复杂战斗动画，也不强制语音。先比较两个不同方向，然后做一份能让我判断的草稿。不要把你写了方案说成已经做出了游戏。

检查它有没有保留约束，而不是只看语言好不好听。允许推进后，阅读草稿，再提出一项具体遗漏，检查下一稿的内容是否真的改变。

更多测试在 `docs/studio/USER_TEST.md`，不用先读架构论文。

## 当前接通的实际路径

```text
用户输入 / 有信息量的数值实验观测
 → 来源标记与有界上下文
 → 语言模块提出记忆、目标、修订（不是直接执行）
 → 合同检查 + 持久目标及版本
 → 有限步数授权
 → 执行一个本地步骤
 → 草稿 / 问题 / 实验动作的实际结果
 → 下一轮上下文、概率更新或验收统计
 → 继续、修订、取消、等待或休眠
```

三个学习通道必须分开：
- 原数值世界：真实动作结果更新有限模型族内的 Bayesian belief。
- 草稿任务：每份草稿的一次显式验收更新 outline/compare/direct 三种工作方法的结果统计，影响后续选择。是粗糙小样本估计，不是通用能力分数或神经训练。
- 表达偏好：有来源的偏好记录，进入后续语言上下文，不改写物理信念或任务成功数。

“巩固”按钮只是从独特验收事件重建同一组统计，不凭重放创造新证据，不代表学习型神经巩固。

## 持续与暂停

状态默认保存在 `user_data/studio/session.json`，每次实际状态提交自动原子保存。退出后再启动同一个目录，会恢复对话、目标、草稿、估计与事件；**执行始终暂停恢复**。key 只存进程内，重启后重新填写。

后台运行以你授予的步数为预算。没有待处理问题、到达等待反馈状态、预算用完或发生错误时不会继续消耗模型调用。程序关闭或电脑睡眠时不在别处继续工作，也没有自动启动服务。

暂停不能撤销已发出的 HTTP 请求或保证不计费；迟到输出不会再执行。请求计数在发送前预留；token 数仅为成功返回时服务商报告的数量，不是独立账单测量。默认生命周期 48 次语言请求，每次最多 2400 输出 tokens；完整输入 token 成本仍随上下文增长，没有精确金额上限。

## 保存、导出与恢复

右上“导出实验”导出全量本地事件与状态，**包括你的对话和草稿**。它不含配置字段中的 API key，但你自己在聊天正文输入的任何秘密仍是正文，请勿这样做或公开分享未检查的导出。

重算一个导出：

```bash
python run.py studio-verify "checkpoint.json"
```

导入到一个新的空数据目录，再启动：

```bash
python run.py studio-import "checkpoint.json" --data-dir "restored_data"
python run.py studio --data-dir "restored_data"
```

命令拒绝覆盖已有生命周期。界面“新实验”先归档旧状态到 `user_data/studio/archive/`，再建立新状态。

**源码绑定：**导出与产生它的源码版本绑定。保留原包与数据一起恢复；不要原地改代码后期待旧状态无条件读取。没有自动版本迁移。v0.1 的数值 checkpoint 不是 v0.2 Studio checkpoint。

## 常见问题

- **刚发送后没有草稿：**发送只处理这一轮语言输入。先检查是否形成了任务，再允许后台推进。普通聊天可能不创建目标，这是正常的。
- **显示手动交换：**默认未连接模型。需要传递完整提示与完整 JSON，或设置一个可用 API。
- **HTTP 400 / truncated：**核对模型 ID、JSON mode、token 参数；输出截断可明确提高输出上限或缩小任务。没有静默额外付费重试。
- **改了设置仍无回复：**检查请求预算、密钥是否因重启清空、本地模型服务是否已启动，点最小连接测试。
- **等用户 / 等验收：**应回答问题或验收当前草稿；重复点自动推进不会自己编造你的反馈。
- **保存失败：**停止推进而不是假称已保存；检查磁盘与目录权限。
- **源码指纹不符：**使用产生导出的原始版本；不要编辑 JSON 绕过校验。
- **“冻结适应”后仍会改稿：**该开关只冻结任务策略统计，语言上下文和数值世界仍可更新，不是全系统 U=0。

## 权限与没有完成的部分

仅监听本机地址。只有本地草稿、有限记忆操作和玩具世界动作。没有 shell、任意路径读写、网络搜索、浏览器控制、发信或真实电脑执行。语言请求仍会把选中的对话与工作上下文送到你明确选择的服务商。

不存在一个经过训练的统一价值起源、开放式自我模型或终身学习网络；数值自我估计不等于模型拥有“自我”。反迎合只做了部分通道隔离，语言本身仍可能迎合、误判或无依据反对，需要你测试。

本轮只在交付容器中实现和验证。未写入你的 EGO/ITL 仓库，未接入任何主链。具体已测与未测范围见 `VALIDATION.md`。
