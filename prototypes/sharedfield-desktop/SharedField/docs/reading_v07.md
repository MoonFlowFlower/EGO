# 一次共同阅读怎样留下变化

日期：2026-09-23。对应 v0.7 有界实现。

用户目标仍是通过真实共同经历持续成长、自然相处。共同阅读是先验证一条因果链的活动入口，不是把整体目标改成文档助手。

## 使用

本机已有的旧经历已通过冻结 v0.6 验证器迁入 `user_data/reading_v07_final/`。双击 `START_READING_WINDOWS.bat`，打开 `http://127.0.0.1:8777/reading`。启动器每次从用户指定文件中仅选带 `codex key` 标签的 OpenRouter 密钥，密钥不写入配置、存档或报告。当前已有程序占用该端口时直接打开页面即可。

启动器固定 `openai/gpt-5.4`，启动前检查公开模型价格。本次验证最多16次请求、按 UTF-8 字节上界与输出限额保守预留最多1美元，错误也不退还预留；账本 `reading_budget.json` 跨重启保留。它不是实际账单金额。页面不能更换连接来绕过此次预算。达到预算边界会停止。

通用入口仍为 `python run.py memory`，其默认数据目录与上述个人验证目录不同，只限制调用次数，不提供美元上限。不要为了续接当前经历而误开一个空目录。迁移个人运行目录时连同 `reading_budget.json` 一起保留。

1. 留下材料原文。一次最多24000字符；来源、全文、段落和内容摘要哈希一起保存。
2. 提出当前问题与阅读方向。模型真正读取所提供的段落，成果中的引用逐字校验。
3. 给出真实纠正。模型基于原文、首次阅读与纠正重读，提出方法、适用范围和例外。
4. 查看并采纳合适的方法。未采纳不算形成方法；不好的建议可以继续纠正。相同方向后续阅读使用当前有效版本，日常聊天可见最近阅读与方法。
5. 换尚未读过、内容不同的新材料。两次请求都有相同原始经历；仅其中一份额外有采纳的方法。先对两份答案评价，再揭示哪份用了方法。
6. 分别评价忠于原文、回应问题、处理条件与边界，附上具体依据。模型或配置不一致、手动外部回复都明确标为无法确认公平比较。

可暂停、结束活动或撤回方法。程序重开保留状态，但不自行发送请求。原文删除会连带清理依赖它的成果、方法和聊天派生内容；独立活动仍保留。外部导出和模型服务商已接收的内容不会随本机删除撤回。

## 能证明什么

工程上连接了原文→真实调用→纠正→候选方法→采纳→新材料对照→评价→保存恢复。学习是有来源的、可撤回的外部方法记忆，不是基础模型权重训练。引用检查只认证字面来自材料，不能保证推断正确。

同历史基线允许直接使用用户纠正，因此比较的是“抽象方法额外带来多少帮助”，而不是故意让基线失忆。一次胜出也不能证明普遍成长；持平和退步必须保留。新材料的答案只是行为意向报告，不能当作在无人提醒时真正履约的证据。

## 根据本轮补充更新的验收重点

用户强调记得约定、自己想到遵守，参考人类社会和心理学，以复刻人性为远期方向。这不是所有提醒都算成长，也不是写一段“我在乎承诺”就算有责任动机。

Gollwitzer 的实施意图研究区分一般目标意愿与把具体情境连接到行动的计划；研究支持在人类特定任务里帮助启动行动，不能直接证明人工系统获得人类心理。可借鉴的工程假设是：已确认约定、适用情境、可执行下一步与冲突处理必须连接起来。来源：[1999原文](https://www.socmot.uni-konstanz.de/sites/default/files/99_Gollwitzer_Implementation_Intentions.pdf)。

Michael、Sebanz 与 Knoblich 的承诺框架关注他人的预期、依赖和持续参与，说明承诺不应仅被表示成一个时间字符串。这是心理学理论框架，不能作为当前系统动机已形成的证据。来源：[The Sense of Commitment: A Minimal Approach](https://pmc.ncbi.nlm.nih.gov/articles/PMC4700132/)。

后续真正的行为验收应覆盖：没有重复提醒仍在适当时机推进；遇到冲突会协商；取消后停止；不把未定提议当已承诺；与“相同历史+承诺表+固定提醒”基线比较。现有系统能检查到期约定并在应用里联系，但这次共同阅读不等于已经实现自主准备、复杂社会动机或完整人性。

## 实现位置

`reading.py` 通过既有事件事务保存活动与方法；`reading_service.py` 接原 worker、暂停代次与 Provider；`/reading` 使用同源 HTTP 和会话 token。v0.6 使用原代码归档逐项复算，再显式迁移，未改用户原存档哈希。源码指纹统一路径分隔符。

源码绑定意味着不能修改运行代码后继续假装同一验证版本。升级应保留当前完整包或做显式验证迁移。原 ZIP、只读解压副本和旧导出都保留在原处。
