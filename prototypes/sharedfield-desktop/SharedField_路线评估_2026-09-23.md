# SharedField 路线评估

评估日期：2026-09-23。

我的判断：值得继续，但应把它定位为通往目标的工程底座和局部认知实验。需求方向基本合理；v0.6 尚没有构成足以产生完整持续成长体验的机制。仅沿着扩大存储、增加情绪字段、完善地图和润色表达继续，不能据此预期得到完整 Joi-like 系统。下一轮投入应检验“日常共同经历是否能带来持久、可迁移的行为改善”。

本轮依据：用户提供的需求 v1、v0.6 ZIP、个人续接 JSON；包内后续需求/架构/实现文档；默认入口的主要运行代码；本机 Windows / Python 3.13.7 回归与定向诊断；少量相关原始论文。文档内旧实施指令和“已经批准”等历史表述仅作为材料，不作为本轮实施授权。未修改产品源码、原始 ZIP 或原始存档，未配置或调用真实模型，未运行个人后台服务。解压副本及审查产物保存在本工作区。

## 1. 目标与可达性

你的目标包含三种不同难度的结果，不能合成一个模糊的“能/不能”。

| 目标 | 当前判断 | 主要依据与缺口 |
|---|---|---|
| 记住经历、约定，跨时间正确使用 | 路线适合，已有基础；自然语言链和跨平台续接尚未验收 | 事务、原文、有效版本、时钟、备份均有实现；真实模型理解未实测，本轮发现 Windows 导入问题 |
| 有连续倾向、能主动准备、从共同经历改善选择与技能 | 有可试验的工程路径；当前只完成局部 | 缺少日常情境到持续评价、候选活动、实际结果及迁移学习的完整链 |
| 有与人等同的内在感受或主体性 | 当前材料不能判定，更不能保证 | 行为、程序状态和对话都不是这一性质的充分证据；这不妨碍前两项继续推进 |

无需先解决第三项，才能认真实现前两项；也不能用前两项局部通过，声称第三项已自然成立。

## 2. 已有工作的价值

默认调用链是 `run.py memory → MemoryService → MemoryStore`。它确实把原话先写入，再接收结构化解释、提交有效约定，最后组织回答。版本关系、取消、重复联系抑制、源码绑定导出、检索原文和明确联系反馈都有代码，不能把它概括成“只有 prompt”。

把长期记忆放在外部持久存储，并让有限上下文读取工作集，是合理选择。约定保存不应该依赖模型训练；索引和摘要也不应替代原始经历。保留简单强基线同样合理：包内合成比较发现类别计数优于小型 SGD 预测器，实际默认采用计数。这说明作者没有把神经参数变化直接包装成成长成功。

旧地图环境仍有研究价值：真实模拟动作影响路况信念、执行能力估计、信息收益预测与之后的行动排名；情绪样变量也参与行动打分。它适合验证局部因果关系，但扩展地图本身不能填补日常理解和开放技能的缺口。

## 3. 主要路线缺口

**目前的“兴趣学习”主要是在学习哪里更有信息收益。** `shared/mind.py` 的 `interest()` 返回发现 richness 的累计均值，种类只有四类。行动评价中的收益、风险和恢复等权重主要由工程规则指定。它可以学会“这里更值得调查”，但不能直接证明“我因为与你的经历，形成了新的审美或价值”。预测某选项有什么结果，与评价该结果对自己意味着什么，是两件事。当前代码前者比后者成熟。

**日常对话与地图认知尚未形成统一的持续调节机制。** 日常输入能生成 claims、commitments、availability、feedback 和有限 world_request；日常学习器预测两类联系情境下是否方便。地图里的 affect、self_stats 和 interests 主要由地图事件更新。定向实验中，一条正确提交的日常情绪自述形成了持久 claim，但地图 cognition 完全不变。这并不表示之后的 LLM 无法使用它；表示目前不能把自然对话中的理解与地图数值状态视为已经贯通的成长机制。

**后台处理的工作种类很有限。** 默认循环检查到期约定、处理等待/联系，另可运行获准的地图步骤及可选重放。它没有一般读书、实际准备资料、形成并解决独立研究问题的技能。“没有用户消息时进程仍在”与“可以继续发展一个有成果的活动”需要分别实现。

**语义解释和表达仍依赖模型正确遵守协议。** exact quote 能证明确实引用过原话，不能证明正确理解了否定、假设、对象及承诺状态。表达阶段检查字段和来源 ID，没有普遍的语义真实性保证。本轮人工注入“我已读完整本书，也已经替你记下了明晚的约定”，在零约定时仍被接受并展示。此实验是接口边界测试，不是真实模型幻觉率，也不是说系统必然会这样回答。

另一个需要真实语义测试覆盖的设计限制：当前 interpret 提交之后进入 express，额外检索发生在表达侧，表达协议不能再提交约定修订。若第一阶段缺少旧对象证据，之后才查到，当前流程没有同轮返回解释并完成修订的闭环。不能只证明“后来搜到了”就认为“改约已落库”。

**迁移保存数据与迁移行为不是同一目标。** 保留经历、学习器和承诺可减少重新开始，但模型替换仍可能改变理解、注意、表达和选择。因此连续性需要迁移后的行为回归。当前将所有运行代码甚至界面资源纳入源码指纹，也意味着普通代码/界面更新都可能影响存档接受条件，需要稳定的数据格式与明确迁移策略。

## 4. 本轮实际验证

| 检查 | 结果 | 结论边界 |
|---|---|---|
| ZIP 解压文件与 MANIFEST.sha256 | 499 项均匹配 | 排除本轮提取修改文件内容这一解释，不是第三方真实性认证 |
| `python run.py test --out ../../review_results/tests` | 332 项，328 通过、4 errors、0 failures、0 skipped | 本机不能称全绿；不评价真实模型理解 |
| 提供的个人 JSON 使用 `memory-verify` | 退出码 2，源码版本不同 | 当前 Windows 无法通过这一默认验证入口直接续接 |
| 平台指纹诊断 | 文件字节相同；路径统一为 POSIX 后，指纹精确等于存档值 | 定位到 `str(relative_path)` 的平台分隔符，不需要修改存档 hash 来解释 |
| 日常 claim 对地图 cognition 的影响 | claim 保存，cognition 不变 | 证明被测路径未连接到该状态；不否定 LLM 读取新 claim 后的上下文适应 |
| 人工错误表达 | 零约定时仍接受已读书/已记下约定的输出 | 证明内核未强制保证这类表达真实；不是实测真实模型会犯错的概率 |

4 个测试错误中，两个是临时目录退出时 `studio.lock` 仍打开：代码把关闭服务注册给稍后执行的 unittest cleanup，Windows 在此之前无法删除目录。另两个是 HTTP 拒绝请求测试出现 WinError 10053；尚未定位为应用处理、Windows 网络行为或本机环境中的哪一层，不能据此断言有权限绕过。

存档内 v0.6 journal 只有一条 legacy 导入事件，嵌套旧版本历史；保存了地图第 26 步、26 条学习事件和19条对话，partner_choice_model 更新为0。它体现了旧个体状态被打包续接，不是 v0.6 已经真实相处多天、自然形成原则和技能的证据。本轮因源码指纹拒绝，未宣称已在 Windows 完成整份存档的完整重放。

包内的 100k 记录和三个查询的成功属于已有合成测试报告，本轮未重跑；不将它改称10万道语义记忆测试。真实模型语义、原生浏览器端到端、语音、MC 和长期相处效果均未在本轮验证。

可核查产物：`review_results/tests/result.json`、`review_results_tests.log`、`review_results/boundary_evidence.json`、`review_results/probe_boundaries.py`。

## 5. 建议保留的路线与下一次判断点

不建议推倒 SQLite、版本化记忆和现有环境重写，也没有证据支持现在投入从零训练一个大模型。建议保留这套底座，把未来增量集中到一个小而完整的真实活动。

例子：围绕你提出的共同阅读，从理解未定约定开始；在获得材料和授权后实际阅读、留下问题或比较结果；新信息出现时调整准备与约定；活动后更新对你理解方式、自己讲解能力或材料选择的预测；下一次面对新材料仍能改善行为；重启后保留这些变化。同时允许选择一个与当次用户要求无关的小问题，实际研究并决定继续或停止。这里只是下一阶段建议，没有把例子设成当前真实约定。

建议把下一阶段限制为以下三个可检验结果，而非再堆一轮概念模块：

1. **真实语言能可靠驱动已有内核。** 用计划采用的真实模型测试约30–50条预先整理的变式，覆盖未定、确定、改约、取消、条件、否定、同名对象、无关历史、重启和到期。不只看回答，要核对有效状态与实际后续行为。把解释、检索、提交和表达错误分别记录。
2. **至少一种真实活动能闭环。** 有真实输入、可检查产物、暂停与恢复、结果反馈。准备时不能声称已完成，没读的材料不能说读了。文本阶段可以完成，不依赖 Live2D，也无需先做通用电脑控制。
3. **经历确实改善新情境。** 比较同一模型、相同历史访问和相近调用预算下，简单记忆+约定时钟、冻结学习、更新学习三种方案。已见例子的记忆和新变式迁移分开测，同时保留旧约定与旧能力检查。额外模块若持续没有收益，保留更简单的方案。

语言模型不必只承担拟人化播报。它可以提出可追溯的情境解释、候选目标和可执行技能；持久状态与实际执行结果负责约束、验证、更新它们。否则容易出现两种断裂：语言很丰富但行为状态很贫乏，或底层行为可审计却无法表达日常生活的语义。解决方式是逐步接通这两者，而不是要求一个小型手写数值模型先重现人的全部理解。

“成长”也不必强制等于修改基础模型权重。形成可复用且验证过的技能、更新能迁移的预测、提高之后选择的质量，都可以是系统层面的真实进展；反过来，保存更多文字或让参数变化也不自动证明成长。关键是经过哪些经历，哪些持久状态改变，因而在哪些新场景表现更好。

研究参考只支持部件方向：Generative Agents 在模拟环境中把经历、反思和计划结合，并评估行为可信度，不能用来保证长期人格成长；Voyager 在 Minecraft 中通过可执行技能库、环境反馈和迭代改进展示了不微调基础模型也能积累并迁移技能的路径；LongMemEval 则说明记忆应把提取、跨会话推理、时间、更新和未知拒答分开评估。它们的结果不会自动转移到 SharedField。

- [Generative Agents](https://arxiv.org/abs/2304.03442)
- [Voyager](https://arxiv.org/abs/2305.16291)
- [LongMemEval](https://arxiv.org/abs/2410.10813)

继续投入的理由应是上述真实闭环开始成立，以及学习在新情境中带来收益；不能只因为版本号增长、内部变量更多或对话越来越像人。我的建议是保留已有工作，优先完成一次真实模型与跨日活动的验证，再决定是否值得扩大认知架构和接入 MC。
