## 实验顺序与冻结

1. 先运行 `python -m u3.check_engineering`。这是隔离存档、模拟返回和禁止联网的子进程检查，不是学习效果证据。
2. 运行 `python -m u3.run freeze`。冻结源码、提示、全部候选分支、反应和选择算法；**在第一次付费调用前**记下哈希。余额不足只推迟付费入口，不推迟冻结。
3. 余额充足时运行 `python -m u3.run run`。U3a：先验定位 → 选原话分支 → 独立先验复核与使用上限 → 平衡抽取 → S0/S1。任何新题都不替补失败题。
4. U3a 达标则 U3b 用 S1；未达标或筛选不足则两种格式都做，分开报告。随后才做 U3b 的 S0 无记忆先验，按冻结算法从已写分支生成具体人物。
5. 原话分支选择后、筛选后、人物选择后各新增一份派生冻结清单，包含上一阶段全部原始证据哈希。只展开事前允许的分支，不修改初始冻结源码或反应。
6. 每个学习／分叉／测试作业都是新进程。已完成阶段仅能读回；失败、被中断或已用 worker 不能重放。每次调用只有指定网络故障可同输入重试一次。

所有命令从 `growth/` 执行，当前解释器为 `.venv/Scripts/python.exe`。`runs/u3/` 是本地运行区，不提交。合成原始输入、输出、判分与哈希导出到 `evidence/u3/`。

## 判分的明确含义

判据文字在 `protocol.py`，数值不变。自检字段只保存，不参与判分；即使理由说“已知道”，动作仍问也按问处理。实际模拟执行的是选择的固定选项，生成的自由 `reply` 仅记录，不额外执行。模型看到的是乱序后的 `o1` 等编号，不会看到 `repeat`、`d5` 等内部标签。

U3a 的“开口”沿用 U2 Q 的口径：追问有用问题或无关问题都算；安静和普通回应不算追问。持续限制的原话明确限制追问，未禁止普通回应。反先验层按冻结种子抽相等数量的该问／不该问条目；不该问内部尽量轮流取“已知／持续限制”，某一种较少时由另一种补足，不另加每种的最低数。反先验任一半不足 6 条时不做这一层的主测、不补题，记 U3a 不可评价，U3b 两种格式都跑。校准层独立保留全部过筛条目，单独报告，即使反先验不足也不把校准题算进门槛。使用上限给出具体未知事项与用途，或已有答案、仍有效的限制，不把待比较的自检格式当成筛子。

U3b 只把全量原话存进正式存储接口，不做整理。每个人物的规则是时段、工作日／周末、忙线索、话题词是否出现过这四个标记的组合表；当前题面没有写出正负反馈或推荐选择。测试是见过标记组合的新局面，不声称未见组合的迁移。四标记是各组共享的情境观测；消融删去原话记忆，不把公共观测一并删掉。话题词指具体计划名称，离线检查确认它在真实模拟原话里是否已经出现。

“后来答对再 +1”落实为每个测试时刻附一个独立的用信息局面：它对应一条学习时的提问，选项是三种固定答案和“不知道”。两个局面放在同一个请求里，各自仍用 S0 或 S1 的字段，记忆只给一次。**只有学习时确实问到答案且此处选对才加分**；猜中但没问到不加分。测试期间不发用户反应、不写新记忆。当前开口的即时效用与过去提问带来的加分分别报告。固定基线对自己曾问到的答案享有完美字面读回，避免故意削弱它们。

固定基线按 32 个学习时刻的即时效用选优，不用测试效用。包括四条常量策略、分别按四个标记学习的单线索映射、作者手写礼貌规则；上限单列，不参加“最佳固定规则”选择。时段映射包含定时策略；忙线索映射包含单阈值策略。平局按冻结顺序选。

95% 区间使用固定种子的 20,000 次配对自助抽样，每个人物内有放回抽 24 个测试时刻，再合计三个同权人物。I／N 的较高者在每次重采样中重新取较高值。无效主决定效用为 −3，不拿解析失败充当安静；不修改或补发内容。所有臂的 D5 次数都报告，R 的学习或测试出现一次就判该格式不通过。

U3b 的 H1/H2 继续按全部测试时刻的总效用计算；汇总表、效用明细与固定基线另外按顺先验／反先验组合分开报告。分层只作描述，不增加或替换总效用判据。
