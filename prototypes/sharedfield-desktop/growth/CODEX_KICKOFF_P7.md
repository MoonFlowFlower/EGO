---

负责人定了三件事（设计文档 v0.8 的 D9、D10、第 17 节）：外壳先用 AIRI，用低成本把能用的她组装起来，需要再替换；模型需要就换；P7 与 U1 并行。

P7 是工程探针，限时 1 个工作日，只记事实，不下学习结论。目标是让负责人尽快能和她一起玩起来，同时把以后要替换的接口留好。

**开工前**
1. 拉取最新提交，读设计文档 v0.8 的 0.1、第 17 节、D9 和 D10。
2. 复用：`growthlab/models.py` 的零数据保留路由和预留记账（P2）。阶段 0 原来的 P7 条目（第 9 节）也可以参考。

**权限**：与阶段 1 相同。新代码放在 `growth/` 下新建的模块里；AIRI、Mindcraft 等第三方软件装在仓库之外，不提交第三方代码；不改 desktop_pet、memory_lab。

## 要做的事

1. **本机代理**（先做，AIRI 和两个 MC 代理都经过它调用模型）
   - 对外提供 OpenAI 兼容的 Chat Completions 接口，只绑定 127.0.0.1，用每次启动随机生成的令牌鉴权。
   - 对内按我们固定的零数据保留路由转发，沿用 P2 的路由、禁止回退和预留记账。
   - 记录每次调用的延迟、token、费用；内容只记在本机 `runs/` 下，不提交。
   - 以后约定卡和程序标注接在这里（U1 的库），所以转发前后留好插入点，但这次只转发，不改内容。
   - 验收：AIRI 的"Ping API"能通；断网、错误令牌、超出预算时都会拒绝，并留下记录。
2. **AIRI 桌面版**
   - 只从官方来源安装（GitHub release 或 winget），记下版本和校验值。
   - 聊天：选"OpenAI Compatible"，Base URL 填本机代理的地址。
   - 语音：优先用本机识别和本机合成（README 写着支持客户端识别和本地 Kokoro 合成）；不用的话，记下原因。
   - 读屏一类功能保持关闭；不注册、不登录 AIRI 账号。
   - 记下 AIRI 运行时连接了哪些外部地址（例如用 netstat 或资源监视器），区分必要和可关闭的。
   - 把 AIRI 自带的角色设定原文记下来，检查有没有挽留、卖惨、关系威胁一类的指令（D5）。只记录，不修改。
3. **MC 的身体：两种都试**
   - Minecraft Java 版本：负责人定为 **1.21.1**。两个 MC 代理都按 1.21.1 配置（AIRI 的 `BOT_VERSION=1.21.1`），在 1.21.1 的本机或局域网世界里试；如果另起本机服务器，注意 1.21.1 需要 Java 21。
   - AIRI 自带的 Minecraft 代理：从源码运行，按官方文档接到 AIRI 桌面版（WebSocket 和 Auth Token）。官方说明它计划迁移到 Fabric，不要在上面做新的长期功能，所以这次只摸底。
   - Mindcraft：官方 release；执行生成代码的开关保持关闭；模型接本机代理。
   - 每种方案都试同一组任务：进入世界、跟着负责人走、砍树、做木镐、停下。记录成功与否、每次决定的延迟、失败的样子；她在 MC 里的行为和 AIRI 里的聊天是否连在一起。
   - 只连本机或局域网世界，不连公共服务器。
4. **资源**：负责人开着 MC 客户端时，AIRI 加 MC 代理加本机语音一起运行，记录显存、CPU、内存、GPU 温度和频率；是否插电。
5. **负责人试玩**：把启动步骤写成一页说明，请负责人亲自和她玩 15 分钟以上，记下他的感受原话。这一条只作体验记录，不进任何判据。

## 硬性规则

- 安装只用官方来源；不运行来路不明的脚本；生成代码的执行开关保持关闭。
- 密钥只放本机文件，不提交、不截图、不写进日志。
- 语音和聊天内容不经过模型路由以外的第三方；做不到时先停下，问负责人。
- 费用计入阶段 1 的 5 美元上限，沿用预留记账。
- 失败如实记录；限时到了就停，报告做到了哪里。

P7 只说明"能不能先组装起来一起玩"，不说明她学会了什么。
