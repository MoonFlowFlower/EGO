# 她的成长设计 v0：从 Crafter 练习场到 MC 共同生活

## 0. 一句话

她是一个"读过攻略的新手"：大模型让她天生"知道"很多，但她从没亲手做过。她在你的陪伴下，先在 Crafter 练习场里练基本功，再到 MC 和你一起生活。

她的成长包括五件事：
1. 把"知道"变成"做到"；
2. 学会这个世界；
3. 学会你；
4. 学会大模型不知道的新规则；
5. 长出自己的偏好和目标。

每一种成长都必须体现在后来的行为里，并留下证据。

## 2. 目标：要证明哪些能力

### 2.1 能力定义（验收标准草案，采纳 GPT 第二轮审核的版本）

| 想要的能力 | 应当观察什么 |
|---|---|
| 有自己的想法 | 判断和她已有的经历、知识、偏好有关；面对讨好压力，仍能说明分歧；遇到有效反证，又会修正 |
| 有自己想做的事 | 能提出具体项目，跨对话、跨重启持续推进；机会冲突时会取舍；失败后调整方法，或者放弃目标 |
| 能理解人的情感 | 能结合情境提出合理解释，并容许多种解释；不确定时会确认；知道什么时候该陪伴、帮忙或安静；会根据你的纠正改变行为 |
| 能学新能力 | 面对训练后才确定的新规则，经过教学或尝试提高表现；重启后保留；换了场景仍会用；规则改变后能改正 |

### 2.2 分阶段要证明的部分【提案】
- **Crafter 阶段**：只证明"能学新能力"，以及"有自己想做的事"中的跨回合项目。
- **MC 阶段**：加上和你共同生活中的理解与协作。
- **"有自己的想法"**：贯穿全程，用分歧记录与修正记录来检验。

### 2.3 声明上限
即使上述验收全部通过，也只说明系统表现出这些可观察的行为。不宣称意识、主观感受、情感、能动性或自主性。"像不像活的"可以作为你的体验指标，但不能单独证明机制有效。

## 3. 出生配置：她生来有什么

### 3.1 继承清单（天生的，必须如实登记）

| 项目 | Crafter 阶段 | MC 阶段 | 说明 |
|---|---|---|---|
| 通用知识 | 大模型对 Crafter / Minecraft 的知识 | 大模型对 MC 的知识（合成表、昼夜、怪物、种田等） | "读过攻略"的来源。Crafter 的论文和代码是公开的，大模型很可能知道它的规则 |
| 感知接口 | 把她**视野范围内**的格子转成文字，加上血量、饥饿、口渴、精力、背包、昼夜亮度 | Mineflayer 提供的结构化信息：附近方块与生物、背包、血量饥饿、时间 | Crafter 提供的全图语义地图和精确坐标是特权信息，**不能给她**（Crafter 论文本身也这样规定） |
| 位置推算 | 根据自己的移动推算位置（类似路径积分） | 同左；Mineflayer 能直接给坐标，是否开放属于【待定】 | 位置推算是继承的；地图上**有什么**要她自己学 |
| 移动控制 | 宏动作："走到视野里的某格""朝某方向走直到看到某物" | Mineflayer 寻路器（A*，环境变化后重新规划） | D2：继承，并登记 |
| 基本动作 | Crafter 原生的 17 个动作（移动、采集或攻击、睡觉、放置、制作） | 挖、放、合成、吃、攻击、跟随你 | 每个动作是否"有效"由游戏判定 |
| 预置技能 | 原则上不预置 | 如果采用 Odyssey 或 Mindcraft 的现成技能，必须单列 | 预置技能不能算作她学会的 |
| 思考 | 云端大模型：理解、计划、写技能程序、分析失败 | 同左 | D3。本地小模型作为兜底，常用路径逐步下放给它 |

### 3.2 后天要学的（只能来自经历）

| 存储 | 内容 | 每条记录必须带 |
|---|---|---|
| 经历记录 | 时间、局面、动作、结果 | 来源：亲历、被教、推断或预测；原始记录归档、可审计、不删除 |
| 认路地图 | 家、水源、树林、石头、洞穴、危险区、路线 | 置信度、最后确认时间 |
| 技能库 | 可执行的技能程序（由动作和宏动作组成） | 适用条件、前置要求、按场景统计的成功率、来源（示范、自练或大模型提议）、熟练度等级（见 3.3）、最后验证时间 |
| 世界事实 | 这个世界特有的规律，包括与"攻略"不同的规则 | 证据（哪几次经历支持它） |
| 自我模型 | 我会什么、各项成功率、弱点、偏好、进行中的项目 | 由实际表现统计得出，不由模型自称 |
| 目标与项目 | 跨天项目：目标、计划、进度、受阻记录、修订历史 | 每次修订的理由 |
| 关于你（MC 阶段起） | 你的习惯、分工方式、偏好 | 来源、可撤销；**常识不得记成"你说过"** |

### 3.3 "知道"与"做到"的熟练度阶梯【提案】

技能和知识在下列等级之间升降，每一级都必须有游戏里的实际结果作证据，模型自己说"我学会了"不算：

| 等级 | 含义 | 升级证据 |
|---|---|---|
| 读到的 | 只来自大模型知识 | 无（起点） |
| 试过 | 亲手成功过一次 | 一次游戏判定的成功 |
| 可靠 | 多次使用中成功率达标 | 例如 10 次里成功 8 次（阈值在预注册中冻结） |
| 已迁移 | 换地图、换名字、换组合后仍然成功 | 新场景下的成功 |
| 已修正 | 规则变化后发现问题，并改对 | 变化后的成功，同时旧场景的版本仍保留 |

这个阶梯就是她的"成长档案"。你能直接看到她从"知道"到"做到"的过程。

## 4. 架构分工【提案】

| 层 | 负责什么 | 在哪里运行 |
|---|---|---|
| 思考层 | 理解局面、做计划、写和改技能程序、分析失败 | 云端大模型（D3）；常用、已验证的路径逐步下放给本地小模型或规则 |
| 她的状态（"她是谁"） | 3.2 节的全部存储 | 本地。这是她的身份所在 |
| 执行层 | 执行技能程序和继承的移动控制 | 本地（Crafter 环境 API；MC 用 Mineflayer） |
| 验证层 | 技能必须经实际执行验证才能升级；失败会降级 | 本地，以游戏判定为准 |
| 动机层 | 在需求、承诺、项目、练习、偏好之间仲裁（见第 7 节） | 本地 |

**身份连续性**：换掉思考层的大模型（云端换另一家，或换成本地模型）后，她的技能、地图、偏好、项目应该都还在，行为大体延续。这一点必须用"换模型测试"来检验，不能只靠设计保证。

这条架构修改了早先"大模型只管语言，小核心独自承担其他所有智能"的共识。理由（来自 GPT 第二轮审核）：那会把理解陌生局面、做计划等最难的部分全压给一个尚未证明可行的小核心。先例：Voyager 用大模型、环境反馈和可执行技能库在 Minecraft 中积累并复用技能，没有微调模型参数。

## 5. 一次经历怎样改变明天的她

### 5.1 学习循环【提案】
1. 你说明目的，或者给出示范（也可以是她自己提出要学）；
2. 她预测"这样做会怎样"，然后亲自尝试；
3. 对比预期与实际，游戏给出结果；
4. 你纠正，或者她自己调整方法；
5. **写入存储**：写进哪个存储、改了什么（新技能、改条件、更新成功率、更新地图、更新自我模型），都要明确记录；
6. 下次用到时，再由结果验证；验证失败就降级。

### 5.2 例子：在 Crafter 里学做木镐
- **第一天**：她"知道"要先砍树、放工作台、再做镐（等级：读到的）。第一次尝试失败了，因为没站在工作台旁边。她对比预期与实际，在技能里加上条件"必须在工作台附近"，再试就成功了（等级：试过）。
- **第二天**：完整重启，换了一张新地图。她调出这个技能，多次成功（等级：可靠）。
- **规则变体**：把"做镐需要的木头数量"改了。她第一次失败，分析原因，修正技能。新世界用新版本，旧世界的版本仍然保留（等级：已修正）。

### 5.3 睡眠整理（每回合或每天结束时）【提案】
- 按标签回放当天的重要经历；
- 更新技能成功率，合并重复的技能；
- 写一段简短日记：学会了什么、哪里失败、明天打算做什么；
- 更新自我模型；
- 淡化没用的笔记。原始记录只归档，不删除。

## 6. 教学方式【提案】

| 方式 | Crafter 阶段 | MC 阶段 |
|---|---|---|
| 示范 | 你用 Crafter 自带的人类游玩界面（`python3 -m crafter.run_gui`，它会录下操作）玩一段，转成她能读的示范 | 你在游戏里做，她通过服务器事件看到你挖了什么、放了什么 |
| 尝试与接管 | 她试；卡住时由你给提示 | 她试；卡住时你接管一小段再交还，这样能覆盖她自己闯进的、你的示范里没出现过的状态 |
| 口头纠正 | 文字提示 | 聊天纠正 |
| 求助 | 她可以求助，但要具体（"我找不到水"），而且有次数预算 | 同左 |

两点注意：
- **示范通常比口头讲更可靠。** 2025 年的 MineCollab 研究发现，用自然语言沟通是协作的主要瓶颈，需要沟通时表现最多下降 15%。两种方式都保留，并分别记录效果。
- **记下每次教学花了你多少时间**，作为重要指标。

## 7. 行动理由与动机【提案】

### 7.1 优先级
1. **紧急需求**：来自游戏的真实状态，例如血量、饥饿、口渴、精力，以及夜晚的危险；
2. **对你的承诺**：你交代的事、和你约好的事；
3. **她自己的项目**：例如"做出铁镐""修一个能过夜的庇护所"；
4. **练习**：练薄弱的技能；
5. **偏好**：在多个可行的活动之间，她更愿意选什么。

### 7.2 原则
- **需求影响优先级，不规定动作。** 具体怎么做，要结合环境和已有目标决定。早期允许用固定脚本当支架（比如"饿了就去吃"），但必须登记，并逐步撤掉；撤掉的进度也要测量。
- **只有"活下去"不够。** 只以生存为目标时，反复取食、躲避、等待就可能已经足够好。探索、练新本事、建自己喜欢的东西，不会从生存目标里自动长出来，所以要保留第 3 到第 5 层。
- **每次取舍都记下理由**，让她答得出"你为什么这么做"。放弃一个目标时也要写明理由。
- **偏好的形成**：从结果和你的反馈中更新，并加阻尼，避免来回摇摆。具体机制【待定】。
- **"白天工作、晚上睡觉"**：Crafter 本身有夜晚危险和精力需求，这是游戏的真实状态。先由你教成习惯，之后允许她看情况调整，比如项目快完成但天要黑了，她决定先回去。我们额外设计的数值（比如"困倦感"）要和游戏真实状态分开登记。

### 7.3 硬约束
- **D5**：你离开、拒绝或关掉程序，不触发卖惨、惩罚或关系威胁。
- **不虚构共同经历**：预测、推断和亲历分开存储、分开表达。
- **不把常识写成"你说过"。**
- **不以互动时长或回复率作为核心奖励。** 这类指标会奖励卖惨。

## 8. 路线与阶段

各阶段可以交叠，暂不规定天数。

| 阶段 | 内容 | 应当发生的成长 | 怎么看出来 |
|---|---|---|---|
| 0 准备 | 本文档、审核、工程探针（第 9 节） | — | 探针事实清单 |
| 1 Crafter 练习 | 原版加规则变体；你录示范；她练习 | 技能形成、重启保留、迁移、纠错、跨回合项目 | 熟练度阶梯、实验 E1 |
| 2 MC 初期照顾 | 你带着她移动、取食，帮她脱困 | 建立动作与后果的联系，知道什么时候该求助 | 求助次数与独立完成率 |
| 3 示范后尝试 | 你做一遍，她换个位置再做 | 从示范中得到能调整的技能 | 换位置后的成功率 |
| 4 独立短任务 | 她自己完成取食、返回、简单采集 | 判断技能是否可靠，处理有限的变化 | 无人帮助时的成功率 |
| 5 安排自己的活动 | 她准备物资、练弱项、继续没做完的项目 | 把多个技能组织起来，维持跨时间的目标 | 项目推进与修订记录 |
| 6 共同生活 | 分工、协商、互相帮助，也有分歧和修正 | 共同经历持续影响以后的判断 | 分叉对照：有没有某段共同经历，后来的选择是否不同 |

**早期"被照顾"和"自主探索"同时存在。** 起步时给她一个比较安全的住处和有限帮助，之后逐步撤掉。帮助有多少、哪些能力是被代劳的，都如实记录。

**与桌宠的关系【待定】**：桌面小屋里的悠小喵，和 MC 里的她，原则上共用同一份身份与记忆存储。两边怎样接通，在 MC 阶段再设计。

## 10. 阶段 1 的判决实验 E1（草案，探针完成后再写预注册）

**问题**：我们额外设计的"她的状态"（技能库、地图、自我模型、验证、睡眠整理），是否真的比"同一个大模型 + 普通历史检索"更会学习？

| 项目 | 设计 |
|---|---|
| 环境 | Crafter 原版，加若干规则变体（改配方、新危险、改名字）。变体用来测大模型不知道的东西 |
| 对比版本 | A：普通历史检索（同一模型，把过去经历的原文检索给它）；B：她的结构化状态；C：B 的消融，屏蔽学习结果 |
| 流程 | 教学 → 练习 → 完整重启（新地图）→ 迁移（换地图、换名字）→ 改一条规则 → 检查旧技能在旧规则下是否保留 |
| 指标 | 游戏判定的成就与存活；重启后被教技能的成功率；迁移成功率；规则改变后的纠错尝试次数；旧技能保留率 |
| 成本 | 模型调用次数、token、费用、墙钟时间、峰值内存、你的教学时间 |
| 规矩 | 教学信息、工具和预算三版一致；模型自称"学会了"不算证据；开发样例上测完成本后，冻结测试集、阈值和停止条件 |
| 判决 | B 没有胜过 A：采用更简单的 A。B 只会原样复现、不会迁移：收窄能力声明。B 胜出：进入 MC |

**提醒**：大模型可能本来就懂 Crafter（有研究让 GPT-4 读 Crafter 论文后直接玩）。所以原版上的好成绩，主要来自"读过攻略"，必须靠规则变体来测真正的学习。

## 11. 预算与隐私【提案，数值待 P2–P7 测完再定】

## 12. 怎样判断她真的长了
- **分叉对照**：同一个存档复制两份，只让一份经历某件事，再放进同一个新情境，比较两份的选择。
- **重启保留、迁移、纠错、消融**：见 E1。
- **换模型测试**：换掉思考层的模型，看她的技能、地图、偏好、项目是否延续。
- **事实以游戏判定和记录为准**，不让大模型来判断真假。
- **"像不像活的"由你盲测**，只作为体验指标。

## 13. 风险与未知

1. **云端依赖**：可用性、费用、隐私，以及服务商换模型对她连续性的影响。
2. **攻略知识掩盖学习**：原版上的进步可能主要来自先验；规则变体能不能真正排除它，尚待检验。
3. **技能库"烂掉"**：2025–26 年的研究发现，大模型写的技能和库常常很少被复用，或者没有可测的帮助。必须测复用率。
4. **长期目标退化成重复脚本**：她的"项目"可能只是机械重复。要测项目的多样性和修订是否合理。
5. **模拟中的理解迁移不到真实相处**：Crafter 里没有你；理解情感要到 MC 阶段才开始测。
6. **从 Crafter 到 MC，能迁移的是架构，不是技能**：两边的动作与规则不同。
7. **用语言教学本身就难**（MineCollab）。
8. **算力、显存与热降频**：需要实测。
