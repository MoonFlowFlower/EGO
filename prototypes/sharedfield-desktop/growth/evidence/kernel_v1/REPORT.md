## 最终结构

`AIRI 输入 / Moonlight 的 MC 输入 → Ego Engine → 同一模型 → 固定 MC 动作 → 真实状态回执 → Engine → 两端同一回复`。

唯一模型入口是 `companion/model.py`；本批十次请求均为 DeepSeek V4.1 Flash / Wafer，单一串行回合入口，conversation_id 为 ego:Moonlight。AIRI 调用本机 OpenAI Compatible 接口，前端历史和角色不作为内核权威状态。MC 身体直接调用官方现成技能，不初始化 Mindcraft Agent、Prompter、Coder 或独立模型。原 AIRI MC 代理仍停用。

内核复用 U1 独立约定库及来源校验、P6 SQLite 持久化和 P7 预算/模型传输。可用库存、合成格、光标分别观察；动作有明确后置条件；重复失败不循环尝试，八次决定耗尽会说明并保留待办。现阶段待办是一条活动目标，尚未实现复杂任务管理。

## 修订及失败

事前清单 CHECKLIST.md 始终不变。v1.0→v1.1 修正 AIRI 官方时间前缀对停止/回显匹配的影响，增加消息通道心跳；v1.1→v1.2 使用官方 broadcast 加单一 instance 目的地，修复原生输入通道缺少 consumer 注册的问题，并将持久动作回执加入后续模型上下文。每次修订均在下一次测试前单独冻结，提示和成功阈值不变，详见 REVISION_LOG.md。

v1.1 两次、v1.2 一次 HTTP 401 保留，均因 AIRI 窗口保有旧本机令牌，在认证层拒绝，零模型/动作。更新后刷新 AIRI 主窗口和 Settings 窗口恢复。连接图标不代表请求认证或回显已经通过。

路由诊断的默认投递返回 no consumer registered；不受限 broadcast 能送达两个 Stage，产生两次无模型的诊断回显。最终限定一个官方 Stage 实例，不用 bypass。v1.2 缓存回显和新 MC 回合各有一次有效 airi_replay；没有额外思考或重复动作。
