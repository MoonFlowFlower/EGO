## 先固定运行规则

1. 产品代理公开稳定别名 `ego-companion`；逐请求按以上顺序尝试，最多 3 个不同端点，各 1 次；不用 OpenRouter 未列名的自动回退，不绕开 ZDR。
2. 仅在请求还没取得上游成功响应时，遇到 404、429、502、503、504、网络连接错误/超时，或端点元数据不再符合要求，才尝试下一项。失败端点冷却至少 30 秒；Retry-After 更长时按其期限冷却。请求之间不排队重发同一路线。
3. 401、402、403、400、预算或隐私校验失败、坏 JSON、内容拒绝、开始输出后的流错误均不借换模型重试。余额不足、OpenRouter 整体故障不能靠换模型解决。客户端只得到固定错误代码；原始错误正文不记录。
4. 每次新上游尝试独立使用原 $5 SQLite 账本预留；未知费用继续占用。所有路线仍限制输入 $1/M、输出 $2/M、非推理输出 2048 token、推理 8192 token、60,000 字节请求、无生成代码执行。
5. ZDR 元数据缓存至多 60 秒；过期刷新失败则关闭请求。日志记录每次选择、失败类型、HTTP 状态、冷却提示、账本 id，以及成功响应实际 model/provider；正文只进忽略的 runs/。云密钥只留进程内存。
6. U1 研究入口仍固定配置、禁止请求内备用。下一轮需建立新冻结清单，从完整 Ua 开始，同组 A/B、Ub、Uc、链条使用同一配置；同家族更强描述臂须重新确认兼容路线。不混入旧 v1，不将本轮可用性检查当作 U1 通过。强模型臂缺少符合上限的 ZDR 路线时依原规则记下并跳过。

- 先用假上游检验真实本机 HTTP 入口：429/404/503 转换、同模型与跨家族次序、401/402/403 拒绝、过期/不合规元数据拒绝、预算预留及未知保留、Retry-After 冷却、固定模式不回退、流开始后不切换、实际路线审计、密钥脱敏。原 19 个代理回归检查也运行。
- 第一次新模型调用前记录配置、实现、验收脚本、此清单的 SHA256。其后不根据在线结果改变提示词、脚本、判据或路线排序。
- 每条路线恰好 3 个独立探针，固定模式、并发 1、无重试：严格 JSON `{"ok":true}`；SSE 文字 `收到`；强制 `echo` 函数调用参数 `{"value":"p7"}`，只读取调用，不执行函数。固定 temperature=0、reasoning=false、max_tokens=512。
- 三项均有有效协议、符合探针输出、费用可核对且没有 HTTP 错误，才标记该路线的本轮烟测通过。失败如实保留；继续检查其它预定探针，不更改输入追求通过。
- 最多 9 次在线调用；本轮新增预留/费用最多 $0.60，原共享总上限 $5 优先。未达到一条完整通过时不宣称更换可用；通过者按预定次序作为运行可用的选择，不宣称永不限流、长期 SLA 或学习质量提升。
