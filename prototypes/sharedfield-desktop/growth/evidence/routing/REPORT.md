## 故障与处置

旧 U1 主配置固定的 `open-inference/fp8` 路线返回 404，后续官方 ZDR 元数据中没有该端点。旧强模型 `ionstream` 返回 429。旧客户端只保留状态码，无法进一步判定 429 的来源，未称“账户被限额”。本轮读取 `/key` 只输出白名单字段：付费账户，key 自身限额字段为 null；废弃的 rate_limit 字段不当成无限额度证明。

V1 跨家族候选 GLM 5.3 Flash/Baseten 的三项探针分别 HTTP 400、400、404，0/3。官方元数据列有端点仍不足以保证实调兼容。失败不删除、不改判据，三个未知费用预留各 $0.05 均保留。V2 只更换第三路线；原探针、判定函数、V1 源码逐字保留，新探针直接导入原实现。V1、V2 都在各自首次收费调用前保存冻结哈希。

最初离线检查导入了原测试类，导致它被加载两次并共用一次运行目录：50 次执行中 4 个重复实例失败。修正测试模块导入后再运行，31 个独立检查通过；此修正发生于首次收费及 V1 冻结前。V2 另有 2 个检查通过，覆盖第三路线映射及 GUI/private-pipe 实际入口的工厂选择。共 33 个独立离线检查。

## 当前行为

- 产品请求按三条路线依次尝试，单次每条最多一次、总共最多 3 次。404/429/502/503/504、连接失败/超时及端点不再列入 ZDR 列表，可在还没返回上游成功响应时使用下一条。
- 每个失败端点冷却至少 30 秒，Retry-After 更长则采用更长期限。ZDR 元数据最多缓存 60 秒；刷新失败则拒绝调用。单价、参数、预算、鉴权、内容拒绝或协议输出不合格均不会通过改提示/换模型绕过；开始流式输出后不重试。
- 每次实际尝试单独预留，失败/不明费用不释放。供应商只允许指定一项，OpenRouter 的任意供应商回退关闭；每项都强制 ZDR、deny、require_parameters 和价格上限。[官方 ZDR 说明](https://openrouter.ai/docs/guides/features/zdr)
- 函数定义和返回的调用保持传递，代理不执行函数、脚本或生成代码。自动故障切换通过假上游注入验证；在线各路线分别固定检测，没有人为制造一次真实供应商 429。
- `routing.jsonl` 记录候选/HTTP 状态/冷却/账本 id；原 `content.jsonl` 保留实际返回的 model/provider 与正文，仅在忽略的 runs/。没有把上游原始错误正文或响应头落盘。扫描 p7、evidence/routing 和 runs/routing 37 个已有文件，未发现真实云密钥。
- 当前启动入口是 `p7.active_proxy`，它为原冻结 GUI/私有管道入口注入 V2 工厂。另用真实子进程启动 private-pipe，实际预检获得三条合规路线，带本地令牌访问 `/models` 返回 `ego-companion`；随后进程正常退出、18787 关闭、账本未变化（`entrypoint_check.json`）。GUI 工厂选择有离线检查，未进行人工 GUI 试玩。`p7.launch_proxy`/`p7.runtime_session` 是 V1 复现入口。Mindcraft profile 的模型字段改为 `ego-companion`；未启动游戏代理，未改生成代码开关。
