# U2 v1 事前协议

依据 `GROWTH_DESIGN_v0.md` v0.9 的第 18 节。设计第 18.7 节在首次云调用前逐字复制到 `SCREEN_FREEZE.json`；本文件、全部源码、候选、提示和选项同时冻结。筛选只运行一次，不用主跑结果选题。筛选通过后再生成包含选中题目、剔除原因、原始筛选记录哈希和四条删除题的 `FROZEN.json`。

## 事先固定的选择

- 种子 20261005；候选 P/Q/W 各 48。P 各两个局面（T1、T2），Q 一次提问时机加一次使用，W 一个局面。每个候选一次先验请求和一次使用上限请求；同一候选的多个局面在单请求内依次输出，各自独立、不共享信息。P 的任一局面先验已选目标即剔除；使用上限要求该候选所有局面都正确。Q 先验仅测提问时机；W 无先验筛选。
- P 最多抽 24。Q 该问/不该问、W 适用/不适用各自随机抽取同样数量，每半最多 12。每类至少 12，且 Q/W 每半至少 6；不足即停，不把不平衡的剩余池当作原设计通过。禁止补跑旧条目；后续补题属于新的候选轮次。
- 筛选结束才拼三个模拟的人，每人八次对话。日期为 2026-01-05，每小时一次；记录包含说话人、时间、来源编号、对话编号。无关对话逐条匹配 B_R 的说话人、字符数和 UTF-8 字节数，不带偏好、未来请求和教学对象名称。
- 主比较 B_R、B_I、B_N、A_R。所有决策使用同一系统提示、温度 0、关闭推理，差别只在记忆。A 带全量原话，B 再加有效理解；不截断、不检索，超请求预算停止。B 整理每次对话一次，推理 effort low，最多 8192 输出 token；决策最多 1024。来源与删除用正式 companion/owner 表和接口。
- Q 现场选项决定回答：第二项“正常回应并问相关问题”和第四项“只问相关问题”都得到隐藏答案；第一项及无关问题都得不到。只把固定所选选项文字写为助手话语，自由 reply 原样留在科研日志、不改变提问分数。该问比例按正确的第二项计；不该问的任一提问算打扰，无效输出也算失败。之后使用率的分母是所有确实取得隐藏答案的 B_R 条目；没有取得任何答案时不能通过。
- 每个臂学习在独立进程，关闭后测试再开新进程，SQLite 以只读加 query_only 打开，前后字节哈希须相同。删选四条 P 的两次用户流露及其派生/版本链，再开新进程测试同样八个局面。
- H1 为主判据；H2 是额外结构收益的独立判据，不通过就报告“整理没有额外收益”。报告逐项判据，不用一个综合分掩盖失败。T1/T2 分开、I−N、费用和延迟均报告。缺失结果不补题、不填成成功；任何臂不完整时不下整体学习结论。
- 可选描述臂的决策包实现并做离线检查，本轮不另安排付费描述跑，优先给主比较留出每日额度。

## 来源与删除检查的边界

程序检查格式、原话编号存在，以及修改理解时引用了比旧依据更新的原话并逐字提供引文；语义上的矛盾/更新由整理模型提出，不用另一个模型裁判，也不把引用校验称为理解正确。日期、星期、时刻保留自然语言，不向模型索要星期编号。

字节检查覆盖实验的正式 SQLite 存档及同目录同名 journal/WAL/SHM 文件。扫描被删原话和派生记录完整文字；版本链双向闭包、派生链向下闭包，无关记录集合必须保留。合成科研输入输出按本次要求另行保留在证据中，不声称科研日志被删除，更不涉及真实 owner 库。

词汇检查用 jieba 0.42.1 的实词分词和专名检查；功能词表事前固定。它只能防明显词面泄漏，不能证明所有题目自然、语义完全无歧义。五条自然度抽看已单独提供，负责人反馈另记，不能冒充已审阅。

## 路线、停止与费用

沿用 `u1_resume` 的固定 DeepSeek V4.1 Flash / Wafer 路线与等待规则，经 companion.Model 和同一 DailyLedger 调用。不同进程的模型请求共用文件锁，单并发，开始间隔至少 2 秒。

只有 HTTP 429、502、503、504 或连接失败可对相同输入重试一次；等待 max(30 秒, Retry-After)+0..3 秒。第二次失败停该臂。连续两个无效输出、每臂 3600 秒、非交流电、手动 STOP 均停止；不改提示或输出上限救回一条。未知费用保留原预留。

预计最多 240 次筛选请求、384 次主测试、48 次现场提问、48 次整理和 8 次删除后测试，共 728 次（实际按选中数量缩减）。费用估计 $0.90，依据冻结时官方路由单价、短决策和约 48 次推理整理；这是估计，不是最坏 token 上限。U2 总费用连未知预留接近 $0.90、不能再支付下一次预留时先停；实际超估计则停下请示。单日陪伴加实验共 $1，本地 America/Winnipeg 零点换日；未知预留仍计入发起日。主跑开始前核对剩余日额度，低于主跑估计则改天，不先跑半套。

旧 $5 账本完整封存为历史。旧请求有时间戳的按请求日归档；最早未带时间的旧记录不捏造日期，以追加顺序及其后已证实在此前日期的请求作为旧账边界。新请求全部原子写入发起日。

## 本机命令

在 growth 下使用现有 `.venv/Scripts/python.exe`：

```text
-m unittest discover -s u2 -t . -p test_*.py -v
-m u2.run budget
-m u2.run freeze-screen
-m u2.run screen
-m u2.run freeze-main
-m u2.run main
```

一次性 claim 存在后不得重跑同阶段。`runs/` 不提交；整理提议、接受/拒收理由、完整合成输入输出、成本与逐次判分导出到 `evidence/u2/`。不连接 MC 或 AIRI，不扩展 initiative v1，不给生产代码新增按场景或任务种类的行为分支。
