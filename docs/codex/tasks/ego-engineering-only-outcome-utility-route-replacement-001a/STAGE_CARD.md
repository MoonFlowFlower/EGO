## 3. Bounded audit

### Hypothesis

A small immutable count-table utility can establish that legal outcome feedback changes serialized internal state, that future predictions consume that state and that fresh-process replay recomputes the same trace through the same package callables.

### Strongest baseline explanation

The utility itself belongs to the lookup/count-table baseline family. A zero/no-update utility can match its initial behavior, and a task-specific lookup can reproduce fixed transcripts. This does not invalidate the engineering objective, but it forbids non-equivalence, specialness, flexible-learning or mechanism claims.

### Strongest reason the task may be invalid

The apparent effect may come from fixture/action-name branching, a stored selected action, static report literals, a CLI-only second predictor, replay that compares stored hashes instead of recomputing or artifact code that signs PASS unconditionally.

### Falsifier

The engineering framing fails if any of the following occurs:

- legal feedback does not change canonical state bytes/hash;
- the declared update fails to change at least one subsequent prediction in the frozen transcript;
- no-update rerun is not a real rerun or is identical to the stateful computed fixture trace after informative feedback;
- fresh-process replay does not start from serialized state and recompute through the same `predict` and `observe_outcome` functions;
- clean observations trigger leakage findings or the planted positive control is missed;
- package or thin-runner production source contains frozen fixture/verdict literals or branches on event/workload IDs;
- CLI, direct API and replay use different prediction/update logic;
- any success verdict is emitted without invoking the fail-closed callable resolver over the exact required-check key set.

### Evidence still insufficient

Source files, green tests, state changes, trace divergence, deterministic replay or a successful smoke report do not prove general learning, transfer, headroom, capability superiority, mechanism validity, product readiness or mainline effect.

### Mechanism versus resemblance

This task tests a bounded engineering function and its state dependency only. It does not test functional subjecthood, agency or consciousness.
