## Search method

### Witness search

The primary search is one precisely frozen, single-threaded, frontier-memory-bounded depth-first branch-and-bound enumeration over canonical primitive actions to exact horizon 89, not a new runtime policy. `frontier-memory-bounded` applies to the active DFS stack, not to total disk usage by the duplicate ledger or streamed evidence. A*, IDA*, beam search, MCTS, randomized search, and implementation-selected alternatives have no formal verdict authority.

The active DFS stack frame contains:

- the complete serialized evaluator state required by the unchanged R1 step/respawn functions;
- `g`, the compact action-index prefix, and the current-path accepted rows;
- clipped frozen support counts;
- the full per-action quotient rows needed to recompute NumPy rank and singular values;
- lifecycle counters.

The search must not copy full prefixes, accepted rows, producer receipts, or evaluator payloads into a global frontier. Full action rows and receipts are rebuilt only for a found candidate by canonical replay. The mandatory exact-duplicate ledger is disk-backed and stores only the 32-byte equivalence digest, compact `g`, and a three-bit-per-action packed prefix; it must not use a Python-object dictionary whose capacity depends on fitting all two million entries in RAM. Formal scratch storage stays under the R2 output directory, is non-authoritative, and may be deleted only after the final digest/count report is durably written.

Action expansion order is exactly:

```text
turn_left, turn_right, move_forward, interact, rest
```

The admissible remaining-action lower bound is:

```text
h(s) = sum over actions max(
  sum of remaining disjoint support deficits for that action,
  13 - current rank for that action
)
```

One future action can reduce at most one disjoint support unit for its action and increase that action's rank by at most one. Therefore `g+h>89` is a sound prune. This relaxation deliberately ignores geometry/path order and never double-counts move/turn navigation already represented by the per-action minima. The analytic root lower bound must be 76.

The root is visited once. A goal is accepted only at `g=89`. A state with `g>89` or `g+h>89` is sound-pruned. Canonical natural respawn is applied before action expansion when legal; exceeding life 4 or respawn 3 is a lifecycle prune.

Exact-duplicate pruning is allowed only on the SHA-256 of canonical JSON containing the complete evaluator state including its clock/lifecycle fields, clipped support vector, remaining budget, and exact ordered per-action feature-row payload. Approximate floating-point state, support/rank-only state, rank-basis-only state, private-map summaries, or prefix hashes are not sufficient. Because remaining budget and clock are in the key, an exact duplicate must have the same `g`; a different `g` is an implementation error. At equal `g`, retain only the lexicographically smaller full action-index prefix, replacing the ledger entry only if that representative is smaller. No other dominance rule is authorized. Producer receipts are not part of the key; a positive candidate rebuilds them by replay. This conservative key may yield almost no cross-prefix pruning, so the two-million-node cap is expected to support a positive attempt or an inconclusive result more often than a complete refutation.

One processed node means entry into the DFS procedure after exact-duplicate screening, whether it becomes a goal, a sound-pruned leaf, or a five-action expansion. The fixed resource cap is `2,000,000` processed nodes per context, cumulative across the entire traversal. If an unprocessed legal child remains when processing the next node would exceed the cap, the result is `WITNESS_SEARCH_INCONCLUSIVE`. `complete_search=true` is allowed only when the root traversal returns after every legal child is processed or sound-pruned, before the cap, and no goal was found.

The primary search digest is a SHA-256 chain in deterministic DFS preorder. Its domain starts with the frozen contract hash and root hash. Every expanded nonterminal node receipt contains processed-node index, node-equivalence hash, `g/h`, and exactly five frozen action dispositions. Each disposition is either a canonical child hash or a named sound-prune receipt with all inputs required to recheck the inequality/lifecycle/duplicate claim. A node not expanded has exactly one node-level disposition instead: `goal` for an accepted `g=89` goal, `horizon_non_goal` for a non-goal at `g=89`, `bound_pruned` for `g+h>89`, or `lifecycle_pruned` for a state already beyond the frozen envelope. The primary and independent implementations must use these identical encodings and must not fabricate five child dispositions for a node-level leaf.

A digest alone has no exhaustion authority. `FROZEN_BENCHMARK_CAPACITY_REFUTED` additionally requires a separately implemented traversal/checker that does not call the primary DFS, starts from the unique root, recomputes every parent-to-child live transition, accounts for all five frozen actions at every expanded nonterminal node, validates every prune or exact-duplicate witness, reaches no unprocessed child, does not hit the cap, and produces byte-equal terminal edge-census digest and processed-node count.

A deterministic lower-bound-greedy macro warm start runs once before primitive DFS. At each canonical state it constructs candidates in frozen target order `v0,v1,v2,v3,v4,empty,wall`, encoded `target_order=0..6`: for `v0..v4`, exact R1 private shortest navigation followed by `interact`; for `empty`, navigation followed by `interact`; for `wall`, navigation followed by `move_forward`. It also constructs the five direct single-action candidates in frozen action order with sentinel `target_order=7`. `terminal_action_order` is always the index in `turn_left, turn_right, move_forward, interact, rest`, encoded `0..4`. Candidates that exceed the remaining budget or lifecycle envelope are rejected. Each candidate is simulated through the unchanged live step functions, including all navigation rows, and ordered by `(h_after, -sum_action_rank_after, primitive_action_count, target_order, terminal_action_order, full_macro_action_index_sequence)`. The first candidate is appended and the process repeats until 89 actions, no legal candidate, or lifecycle exhaustion. It uses no cause ordering, model/loss/verdict, future panel truth, or manual context-specific target list. If the resulting 89-action sequence passes the full primitive canonical replay and all witness constraints, it is the context's positive certificate and primitive DFS is skipped for that context. Otherwise its failure has no verdict authority and primitive DFS starts from the untouched root.

### Panel search

For every frozen rollout ID, a deterministic breadth-first navigation search may vary the order in which it claims the unchanged target multiset. It may use only `turn_left`, `turn_right`, and `move_forward`; it may not interact, rest, reset, teleport, or cross a natural terminal. On entry to a state, if its front token is still required and its public checkpoint hash has not already been claimed in the current context, exactly one matching target is claimed without changing evaluator state. The remaining target multiset and within-context claimed hashes are part of the search state. Previously retained hashes from earlier rollout IDs in the same context are forbidden when solving later rollout IDs in ascending order. Different contexts never dedupe against one another.

The panel BFS minimizes primitive navigation action count and then the frozen action-index sequence. Its logical state contains the canonical panel evaluator state, remaining target multiset, rollout-local claimed hashes, and the current context's previously retained hashes. Storage must be compact: queue entries contain only canonical state/content digests, compact remaining-multiset/claimed-hash references, and parent/action pointers; canonical evaluator-state blobs live once in a disk-backed content-addressed store. The queue must not copy full prefixes, full rows, or evaluator JSON into every entry. The fixed cap is `250,000` processed nodes per context/rollout. Hitting the cap with an unprocessed legal child yields `PANEL_SEARCH_INCONCLUSIVE`. A positive panel is accepted only after all frozen support, cell, rank, and construction fields independently recompute. Complete failure of this sequential constructive search is `PANEL_CAPACITY_NOT_CERTIFIED`, not a proof that no joint panel exists.

## Verdict priority

Exactly one verdict is emitted in this order:

1. `BLOCKED_001H_R2_PROVENANCE_LEAKAGE_OR_RECOMPUTE`;
2. `INVALID_POSTRESULT_RESCUE`;
3. `CONTROL_ENVELOPE_OR_ACCESS_PARITY_BROKEN`;
4. `SEARCH_IMPLEMENTATION_INVALID`;
5. `FROZEN_BENCHMARK_CAPACITY_REFUTED` when at least one context has independently verified complete DFS witness-search exhaustion;
6. `WITNESS_SEARCH_INCONCLUSIVE` when any context reaches the fixed processed-node cap without a certificate and with at least one unprocessed legal child;
7. `PANEL_SEARCH_INCONCLUSIVE` when all witness certificates exist but any context/rollout reaches the fixed panel-search cap;
8. `PANEL_CAPACITY_NOT_CERTIFIED` when all witness certificates exist, panel search completes within cap, but any panel certificate fails;
9. `EXISTENTIAL_CAPACITY_CERTIFICATE_FOUND` when all witness and panel certificates pass.

`EXISTENTIAL_CAPACITY_CERTIFICATE_FOUND` does not change the R1 verdict. It only establishes that R1's constructor was incomplete on the same contaminated structural surface. `WITNESS_SEARCH_INCONCLUSIVE`, `PANEL_SEARCH_INCONCLUSIVE`, and `PANEL_CAPACITY_NOT_CERTIFIED` do not close or refute that surface; they stop R2 with capacity unresolved. One completely refuted witness context is sufficient to refute the all-context conjunction. If no context is completely refuted and any witness search hits its cap, the witness result is only inconclusive.
