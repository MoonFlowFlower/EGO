# Collision Record — EGO-CANONICAL-MECHANISM-INTEGRATION-001A

Status: `FROZEN_BEFORE_IMPLEMENTATION`

## Real objective

Produce one testable successor in which learned prediction/update history is
load-bearing, while preventing another default-off shadow ladder or UI-only
behavioral resemblance result.

## Candidate A — run the existing EgoDesktop PET P2

- Evidence produced: visible drift session, learner toggle trace, product replay.
- Strongest cheap baseline: schedule-aware policy, count table, or fixed
  prediction-error threshold reflex.
- Leakage/hard-coding risk: high; drift schedule is known and the C-forage audit
  already disclosed a fixed threshold plus direct write.
- Smallest falsifier: frozen model updates retain the re-observe reflex or a
  schedule-aware static arm matches post-shift performance.
- Expected failure: attractive UI result with no mechanism attribution.
- Decision: rejected as the canonical successor. Preserve as historical
  engineering evidence; do not run P2 as a substitute.

## Candidate B — connect VirtualCatPSPC directly to EgoDesktop

- Evidence produced: visible world-model predictions and actions.
- Strongest cheap baseline: Electron-side scripted playback of lab outputs.
- Leakage/hard-coding risk: maximum; Electron or the bridge becomes a second
  state/policy authority and replay may trust stored outputs.
- Smallest falsifier: headless reconstruction cannot reproduce the session
  without Electron or adapter-local hidden state.
- Expected failure: a second kernel and schema split.
- Decision: rejected.

## Candidate C — K0 canonical state plus VirtualCat-derived adapter plus
## observer-only EgoDesktop

- Evidence produced: one event-sourced prediction/error/update/proposal chain,
  with default-off visible observation and recomputing replay.
- Strongest cheap baseline: schedule-aware static, count-table, fixed-reflex,
  observation-only decoder, and stored-action replay implementations under equal
  access.
- Leakage/hard-coding risk: model checkpoint or optimizer state hidden in the
  adapter; lab fixture identities leaking into observations; renderer-derived
  evidence.
- Smallest falsifier: K0 cannot serialize/recompute model state, or any control
  baseline matches the candidate under the preregistered metric.
- Expected failure: K0 Foundation's existing generic transition cannot carry
  mechanism state without a minimal canonical extension.
- Decision: selected conditionally. M1 starts with this exact feasibility test;
  failure closes or redesigns the route instead of bypassing K0.

## Strongest reason the selected framing may still be invalid

VirtualCatPSPC's current lab advantages may be task-distribution artifacts. A
lookup/count baseline with the same observation and training access may match
the integrated model. Integration success would then be engineering assembly,
not evidence for a learned world-model advantage.

## Falsifier and insufficient evidence

Falsifier: equal-access controls match the candidate, or update/PE ablations do
not remove the later proposal change.

Still insufficient: an app launches, a trace exists, replay hashes match, the UI
looks adaptive, or the candidate beats a deliberately weak static policy.

## Selected approach

Candidate C only, with a feasibility stop before K0 core edits and with the full
baseline/ablation/replay contract frozen in `STAGE_CARD.md`.
