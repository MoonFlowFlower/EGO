## Packet-stream framing and hash

`PREREQUISITE_STREAM_V1` uses this exact binary framing:

```text
magic = ASCII "EGO001DPS1\n"
for each record in exact plan order:
  length = unsigned 64-bit big-endian length of canonical UTF-8 JSON bytes
  payload = canonical UTF-8 JSON bytes of one PREREQUISITE_CASE_RECORD_V1
trailer = canonical UTF-8 JSON bytes of STREAM_TRAILER_V1, itself length-prefixed
```

`STREAM_TRAILER_V1` has exactly:

```text
schema_version
execution_plan_sha256
record_count
case_id_digest
payload_sha256
shard_receipts
```

`case_id_digest` is the I1 plan's `SHA256_LENGTH_PREFIXED_CASE_IDS_V1` over exact case IDs. `payload_sha256` is SHA-256 over every record frame from its eight-byte length through payload, excluding magic and trailer. Shards cut only between frames. `shard_receipts` are ordered and hash-chain adjacent shards. The canonical packet SHA-256 used by `GATE_REDUCTION_V1` is:

```text
SHA256(ASCII "PREREQUISITE_STREAM_V1\x1f"
       || execution_plan_sha256 ASCII
       || case_id_digest ASCII
       || payload_sha256 ASCII
       || decimal_record_count ASCII)
```

The consumer validates one record at a time against the next lazily generated expected case and updates count/digests incrementally. Reorder, duplicate, missing, surplus, malformed length, truncated payload, invalid child schema, or trailer mismatch fails closed.

## Primary, fresh replay, and independent recomputation

Any shared utility is limited to canonical JSON, SHA-256, framed I/O, strict integer parsing, and immutable authority-byte loading. Statistical or decision logic may not be shared.
